# Haonan SDD Skills

一套供 Codex 使用的规范驱动开发（SDD，Specification-Driven Development）Skill 系列。它把从产品想法到上线交付的工作拆成可交接、可验证的研发资产，而不是让每轮对话重新猜测需求、状态、接口和验收条件。

## 适用场景

- 从模糊想法规划一个新产品或新功能。
- 将需求、原型、架构、详细设计和代码实现保持可追溯。
- 为包含 AI Agent、敏感数据、异步任务或外部交付的项目补齐风险控制。
- 在既有仓库中按最小工单实施、验证、发布和交付文档。

这不是要求所有项目完整跑完 17 个 Skill。先用 S000 判断当前缺少什么，再选择最少且足够的一组。

## 推荐路径

```text
S000 → [S001] → S002 → S003-1 → [S003-2] → S004
→ S005-1 / S005-2 / S005-3 / S005-4 → S006 设计评审
→ S007 → S008 → S009 + S010 → S006 发布门禁 → S011 → S012
```

方括号表示按需使用。四个 S005 分支围绕字段、权限、错误和状态等共同契约并行，而不是机械串行。S009 的测试计划可在 PRD 阶段开始，S010 的威胁模型可在 HLD 阶段开始。

## 快速开始

1. 面对新想法、改动或现有仓库，先调用 `$haonan-s000-pmp`，确定阶段和最短路径。
2. 新产品通常从 S001/S002/S003-1/S004 开始；明确的小改动可从 S007/S008/S009 开始。
3. 只有在字段、权限、状态与错误契约明确后，再让 S005 的分支并行细化。
4. 编码前运行 S006 设计评审；发布前再运行一次 S006，核对测试、安全、迁移和回滚证据。

## 发布状态

跨环境任务使用 S000 的发布状态契约，分别记录源码、Git、服务端、数据库、H5/后台和小程序。`GIT_PUSHED` 不代表生产已部署，`PROD_VERIFIED` 不代表小程序已上传，提交审核也不代表正式发布。

默认在本机完成集中修复和完整回归，冻结候选 commit 后再经过 S006 发布门禁和 S011 受控部署。每次发布保留 Release Manifest，关联构建物校验和、数据备份/迁移、配置变量名、验证证据和回滚路径。

每个关键事实都应标明 `EXPLICIT`、`INFERRED` 或 `UNKNOWN`；交付状态只使用 `PLANNED`、`CREATED`、`OBSERVED`、`VERIFIED`、`BLOCKED`。没有真实执行证据时，不把设计稿、配置或推测写成 `VERIFIED`。

## 目录与校验

每个 Skill 目录至少包含 `SKILL.md`；部分 Skill 还带有 `references/`、`scripts/` 或 `agents/openai.yaml`。修改本系列后，可运行：

```bash
python3 haonan-s000-pmp/scripts/validate_pipeline.py .
```

该脚本检查目录清单、前置元数据、相对资源链接、界面元数据、跨 Skill 名称引用和发布状态契约。

## 使用边界

- S000 负责路由与编排，不替代下游专业设计。
- 各 Skill 默认输出决策、依据和可验证产物；不把未知项伪装成事实。
- 代码修改、生产部署、外部写入和有副作用的安全测试仍需明确授权。
- 这套 Skill 提供研发过程的结构，并不能替代对业务、法律、合规或安全风险的独立判断。
