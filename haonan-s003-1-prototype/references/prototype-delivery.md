# 原型交付与验证

## 按模式选择

`AUDIT` 引用实际原型路径和审查结果，不强制修改文件。`SPEC` 输出完整交互规格；用户要求可操作原型时交付 HTML 或指定格式。`BUILD` 生成或修改授权的可运行原型。

自包含 HTML 采用完整文档结构，内联必要 CSS/JavaScript，每个核心屏幕有稳定 ID。离线要求只在用户需要时启用，既有工程允许继续使用真实依赖和构建方式。

每个主要操作具有可观察反馈；原型演示与实际后端调用明确标注。数据和工具使用遵守用户限制，不伪造已经实现的能力。

## 映射字段

屏幕记录 `screen_id`、名称、角色、入口、退出、需求和验收 ID、适用状态、原型目标及当前状态。

流程记录操作者、前置、步骤、关键决定、失败恢复、完成结果和屏幕位置。缺少对应实现的需求保留在映射中。

图像或第三方资产确有使用时记录来源、许可、实际文件和用途；生成资产注明实际工具及来源记录。没有图像需求时不创建无关图片。

## 检查

使用具有 `scripts/requirements.txt` 依赖的 Python：

`validate_prototype.py /absolute/path/to/prototype.html`

检查 HTML 文档、主内容和操作元素，列出屏幕及控件数量。明确要求离线自包含时追加 `--self-contained`，检查外部引用与 CSS 资源。

此脚本只做结构检查。浏览器导航、输入、提交、返回和关键状态需另行执行，视觉检查仅在允许条件下使用。报告分别列出结构、交互和视觉证据。

通过 JavaScript 动态生成主内容或控件时，静态文件不能证明其存在；脚本输出 `RUNTIME_REQUIRED` 并返回退出码 2。使用获准的浏览器行为检查继续验证，不将这种情况直接认定为产品缺陷或验收通过。
