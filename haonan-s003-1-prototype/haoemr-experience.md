# Haonan S003-1 产品原型

## 模式与产物

- `SPEC`：创建屏幕、流程与状态规格；用户要求原型时交付可操作 HTML 或指定原型格式。
- `AUDIT`：读取既有原型、需求和实现，输出覆盖及缺口；只读审查不要求新增 HTML 或图片。
- `BUILD`：按已授权范围创建或修改可运行原型，并验证核心交互。

沿用用户确认的风格、平台与交互方向，不因审查或修复重新设计产品。需要原型时优先复用已有工程或使用自包含 HTML，交付格式由用户要求和已有工作方式决定。

## 目标与现状

目标范围依据用户最新明确决定、批准 PRD 和确认设计。当前代码、路由和画面用于记录已有实现；缺少实现的屏幕和动作保持缺口，不能从目标中删除。

记录 `EXPLICIT / INFERRED / UNKNOWN`，原型交互不能自行决定计费、权限、临床或其他业务规则。只有实质影响目标的未知需要提问，已给出的输入不重复索取。

## 设计流程

1. 从用户任务建立角色、入口、步骤、结果、退出和错误恢复，保留需求与验收 ID。
2. 枚举必要页面、弹窗、抽屉、条件分支和深链；已有路由仅是当前实现盘点的一部分。
3. 每个主要操作指定预期反馈、输入校验、状态变化、数据来源和后续结果。
4. 按适用性覆盖加载、空、错误、权限、部分数据、成功、撤销、长内容及不同目标视口。
5. 明确页面间身份和业务对象传递；说明切换、刷新、返回后保留或清除哪些内容。
6. 使用真实授权资料；如允许原型演示数据，明确标记用途和未实现能力。用户禁止模拟时遵守该限制。
7. 生成或修改获准的原型，检查关键操作、焦点、导航和恢复；文件存在或按钮显示不能证明流程可用。

交付规格与检查方法见 [原型交付](references/prototype-delivery.md)。

## 图像与验证

视觉工具和图像生成只在用户请求、允许且对本次产物必要时使用。复用现有图标及合法资产；没有新增资产需求时不强制生成图片。生成资产记录来源和实际文件，不能将程序产物冒充图像生成结果。

HTML 结构检查使用 `scripts/validate_prototype.py`，依赖列于同目录 `requirements.txt`。脚本仅证明检查过的结构；真实交互需要浏览器行为证据，视觉一致需要用户允许的视觉验证。

## 交接

交付屏幕与状态映射、流程、实际原型路径、已执行检查、未完成能力及未知项。S003-2 承接适用视觉工作，S005-4 承接实现状态，S007/S009 承接完整验收动作。多阶段状态遵循 [交付记录](../haonan-s000-pmp/references/delivery-ledger.md)。
