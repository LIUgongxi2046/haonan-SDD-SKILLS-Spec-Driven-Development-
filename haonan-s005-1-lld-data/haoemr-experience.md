# Haonan S005-1 数据详细设计

## 模式与输入

`DESIGN` 设计数据与查询，`AUDIT` 检查完整性及风险，`MIGRATION` 设计迁移与恢复。读取需求、架构、现有 Schema、合法样本、访问模式、来源、质量、隐私和保留要求。

依据访问模式、规模、可靠性和成本选择存储，不默认同时使用关系库、向量库、图数据库和搜索引擎。样本不足时给出逻辑草案，实际分布、阈值和性能保持未知。变化中的来源条款、许可和 API 核对官方来源。

## 设计要求

1. 数据源登记所有者、许可、用途、采集方式、更新频率、敏感级别、版本与校验和。
2. 定义实体、稳定标识、关系、枚举、主键、唯一约束、索引、分区和所有权；身份显示与实际 ID 必须来自一致记录。
3. 建立产出到使用的关系：业务字段、配置和知识记录由谁创建、谁查询、何时生效、如何失效，以及结果如何被业务采用。
4. 设计采集、校验、标准化、去重、脱敏、分块、富化、发布、隔离与删除，明确失败记录、幂等和重放。
5. 知识审核、发布、索引和应用引用分别设计；原始资料、发布版本、索引版本和运行引用可以核对，不能只有展示或统计记录。
6. RAG 明确 chunk、metadata、来源引用、过滤、召回、重排、更新与删除传播；阈值从需求或测量取得。
7. 数据质量规则记录观测、阻断、复核和修复责任；只有规则登记而无法运行时维持未实现状态。
8. 批量导入保留来源、许可、版本、去重键、未匹配项和抽样证据，不能把生成内容标为官方原文。
9. 迁移设计兼容、备份、逐键或内容校验、关联完整性、业务接口读取和恢复方法；新旧数据库选择及数据连续性明确。

详细字段见 [数据规范](references/data-contract.md)。JSON Schema、SQL 和目标配置使用成熟校验器，实际通过才记录相应语法证据。

## 验收与交接

行数相同不能独立证明内容正确。迁移与导入核对关键记录、关联、内容、幂等及业务可读性；查询过滤与空结果需要解释依据。数据使用方未接入时，对应业务需求继续保留。

向后端交付事务与查询规范，向 Agent 交付检索与引用边界，向前端交付身份与版本字段，向 S009 提供数据生命周期与业务消费验收。状态遵循 [交付记录](../haonan-s000-pmp/references/delivery-ledger.md)，设计文件完成不代表数据功能验收通过。
