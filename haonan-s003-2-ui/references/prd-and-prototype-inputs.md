# PRD 与原型输入推导参考

## 1. 只有 PRD

按以下顺序提取：

1. 用户角色、权限和使用环境。
2. 核心目标、任务和成功指标。
3. 功能需求、用户故事和验收条件。
4. 业务对象、状态和异常规则。
5. 平台、尺寸、品牌、合规和内容限制。

把每个需求映射到入口、操作页面、反馈状态、结果页面和恢复路径。不要在 UI 阶段自行定义未写明的计费、权限或数据规则。

## 2. 只有原型、线框图或截图

逐屏记录：

- 屏幕名称、入口、退出方式和可能的前后屏。
- 导航层级、控件、内容类型、交互线索和可见状态。
- 明显缺失的加载、空、错误、权限和确认状态。
- 无法从画面确认的后台规则和数据来源。

可见内容标记 `EXPLICIT`；为形成可用交互而补充的内容标记 `INFERRED`；后台规则标记 `UNKNOWN`。

## 3. 冲突处理

默认优先级：

1. 当前运行代码和真实路由。
2. 用户最新明确决策。
3. 已批准 PRD。
4. 已确认原型。
5. 合理推导。

发现冲突时记录双方证据、影响范围和建议，不静默覆盖。

## 4. 提问门槛

只有以下情况需要暂停：

- 不同答案会改变页面数量、品牌方向或核心任务流。
- 涉及商标、版权、真实个人信息或受限内容。
- 用户是否允许改代码不明确，而任务需要写入工程。
- 目标平台或交付格式会导致不可逆工作差异。

其他缺口先使用可逆假设继续，并写入 `assumptions-and-open-questions.md`。
