# UI 输入与目标依据

## PRD 输入

提取角色、使用环境、目标、流程、验收、对象、状态、权限、平台和品牌要求。每项需求映射入口、操作、反馈、结果与恢复路径。后台规则缺失时保持未知，不在 UI 阶段自行制定。

## 现有原型与实现

记录屏幕、入口、导航、弹层、主要控件、数据来源和状态。代码与画面只说明当前实现，缺少的已批准功能继续保留在目标范围。

目标依据依次为用户最新明确决定、批准需求、确认设计、明确标注的推导。现状依据运行结果、源码、实际路由及其他可核查材料。冲突同时记录目标与现状，不能静默缩减目标。

## 未知与约束

只有必要答案会改变核心流程、实质范围或授权动作时提问。其他推导注明来源及影响，沿用已经确认的风格、平台、修改范围和工具限制。

假设记录 ID、来源类型、依据、内容、影响和待验证条件；新建议与批准范围分开。
