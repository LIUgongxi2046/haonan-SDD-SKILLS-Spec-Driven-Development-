# Haonan S003-2 UI 设计与验证

## 模式

- `DESIGN`：定义视觉系统、组件、页面及适用状态。
- `AUDIT`：检查既有界面和资产，输出有依据的问题与未验证项。
- `IMPLEMENT`：在用户已授权范围内修改界面并运行受影响验证。

新视觉方向、已有界面复用和局部修复分别识别。已有批准方案时继承；单页修改不追加菜单或全局设计。只读审查不要求生成新资产或新页面。

## 范围与来源

目标依据用户最新决定、批准需求和确认设计；代码及当前界面记录实现现状。缺少实现的目标页面仍纳入范围。推导和未知分别标记，不从视觉资料决定后台业务规则。

按需要读取：

- [输入与目标依据](references/prd-and-prototype-inputs.md)：处理 PRD、原型、现有代码及冲突。
- [页面和状态覆盖](references/coverage-and-states.md)：盘点实际修改范围与完整验收。
- [视觉系统](references/visual-system.md)：定义或维护 Token、组件及资产一致性。
- [交付规则](references/delivery-and-slicing.md)：确定产物与来源清单。
- [质量检查](references/qa-checklist.md)：执行或审查界面验收。

## 设计与实施

1. 记录平台、视口、页面、业务动作、风格、品牌、工具限制与用户授权。
2. 将需求映射到页面、弹窗、交互状态、结果及错误恢复；额外建议不混入批准分母。
3. 定义语义 Token、字体层级、颜色、间距、组件尺寸、换行、焦点、状态和响应式行为。
4. 共享组件变更建立实际使用页面清单，检查继承规则，不能只修改和验证示例页面。
5. 覆盖长内容、结果出现、空列表、加载、错误、权限、弹窗、缩放和键盘操作；检查滚动容器、固定导航、标题、浮层和底部内容的相互影响。
6. 自适应规则明确可用区域、最小尺寸、超出内容后的滚动方式，保持用户确认的导航和页面结构。
7. 资产按槽位、尺寸、来源和许可选择；新定制图像确有需要且用户允许时使用可用生成能力，复用资产不强制重新生成。
8. `IMPLEMENT` 检查当前文件与未提交改动，修改后运行对应类型、构建、资源及交互回归；业务规则和接口变化单独核对授权及需求。

## 验证与声明

用户禁止视觉工具时遵守限制，可进行获准的 DOM、计算样式、可访问性与行为检查；这些证据不能替代未执行的视觉检查。声称视觉一致时，必须在获准条件下核对相同视口和状态。

使用 `scripts/audit_ui_delivery.py` 验证交付清单、引用、文件及图片有效性。依赖列于同目录 `requirements.txt`。脚本不生成产品图片，不执行视觉识别，也不证明交互或视觉效果。

## 输出与交接

按所选模式交付设计、实际修改或审查记录，附页面与状态分母、资产来源、检查结果和未验证项。完整设计保留 Token、组件、状态和资产；局部任务引用现有规范与实际变更，避免无关重复产物。

向 S005-4/S007 传递范围、组件和动态状态要求，向 S009 提供受影响页面及行为检查。状态遵循 [交付记录](../haonan-s000-pmp/references/delivery-ledger.md)，页面存在和校验器通过不能替代完整 UI 验收。
