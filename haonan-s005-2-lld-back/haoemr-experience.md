# Haonan S005-2 后端详细设计

## 模式与依据

`DESIGN` 创建接口及服务设计，`AUDIT` 核查当前能力，`MIGRATION` 设计兼容演进和数据恢复。读取 PRD、HLD、数据规范、当前代码、调用方、NFR 和安全约束；保留现有框架及工程约定。

缺少材料时标记事实、推导与未知。只阻塞受关键未知影响的动作。依赖或 API 用法不确定时查看对应版本官方资料，不默认 Redis、Kafka、SSE 或其他基础设施。

## 设计要求

1. 为服务定义职责、数据所有权、调用方和访问边界。每个承诺动作映射到实际业务处理及可观察结果。
2. 接口包含身份、权限、请求、响应、错误、分页、版本、幂等和兼容语义；使用方及错误后的恢复动作明确。
3. 状态转换绑定实际业务事实；保存记录、确认请求、执行成功和收到外部回执分别定义。
4. 配置发布后明确运行时读取位置、版本选择、作用范围、缓存失效和实际效果。没有执行器时不能把配置状态命名为业务已执行。
5. 定义事务、并发冲突、锁或版本、重试、重复投递、部分失败和取消；异步任务补租约、超时、失败队列、重放与结果通知。
6. 权限包含主体、资源、动作与数据范围，同时说明合法用户如何取得前置并完成操作。
7. 外部依赖定义超时、有限重试、失败边界、限流和观测；内部投影不能当作外部送达证据。
8. 启动核查配置、秘密及依赖，禁止无提示启用测试模式或用占位结果冒充实际服务。
9. 健康检查区分进程存活、依赖就绪和核心业务可用；日志与审计记录来源和结果，保护敏感内容。
10. Schema 演进包含数据保护、兼容、迁移、对账及恢复，沿用项目工具校验有效语法。

参考 [后端规范](references/backend-contract.md)。Agent 内部编排由 S005-3 设计，后端明确可调用能力与授权边界。

## 验收与交接

写操作验收包含合法调用、服务端变化、重新读取和后续业务结果；拒绝路径单独测试。只读接口验证数据来源、范围与权限。注册数量、返回码或单表 CRUD 不自动代表完整模块。

向 Agent 与前端提供实际接口、身份字段、版本、时序、错误与恢复要求；向 S009/S010 提供成功和拒绝检查。跨层任务使用 [交付记录](../haonan-s000-pmp/references/delivery-ledger.md)，接口格式通过与业务验收分别记录。
