# Haonan S005-2 后端 LLD

## 定位

把 HLD 的服务边界细化为可实现、可联调、可测试的后端契约。保持框架与供应商中立；有现有代码库时优先延续其惯例。

## 工作模式

- `DESIGN`：创建后端 LLD 和接口契约。
- `AUDIT`：审查 API、事务、权限、失败处理与可观测性。
- `MIGRATION`：设计兼容演进、双写/回填、灰度和回滚。

## 输入处理

读取 PRD/HLD、数据契约、现有代码和接口、调用方需求、NFR 与安全约束。缺少某一上游文档时可用明确假设形成草案；只有会造成不可逆协议或数据错误时才 `BLOCKED`。

依赖版本、框架特性、云/第三方 API 发生变化的可能性高时，核查官方文档。不要默认 Redis、Kafka、微服务、SSE 或某个验证库。

## 设计步骤

1. 盘点现有运行时、框架、模块、代码约定和部署边界。
2. 为每个服务/模块定义职责、数据所有权、调用方和禁止跨越的边界。
3. 设计接口：认证、请求/响应、错误、分页、版本、幂等和兼容策略。
4. 定义事务边界、并发冲突、锁/乐观版本、重试和重复投递语义。
5. 仅在需要时设计队列/任务：状态、租约、超时、取消、重放、死信和结果通知。
6. 定义主体—资源—动作—范围授权、审计和敏感数据处理。
7. 为外部依赖定义超时、重试、退避、熔断、降级和限流。
8. 建立日志、指标、追踪、成本与业务事件，避免记录敏感原文。
9. 形成接口/错误/事件/状态契约和可执行验收清单。

## 必须交付

- 模块/服务职责和依赖图。
- API/DTO/事件契约及版本策略。
- 统一错误目录和客户端可恢复性说明。
- 事务、并发、幂等和异步状态机。
- 认证授权、租户隔离、速率限制和审计契约。
- 外部依赖故障矩阵与可观测性设计。
- 数据迁移/兼容/回滚策略（适用时）。
- 对前端与 Agent 调用方的握手清单。

模板字段见 `references/backend-contract.md`。

## 质量门禁

- API 示例符合选定 OpenAPI/JSON Schema/Protobuf 版本并实际通过校验后才 `VERIFIED`。
- DDL 语法与目标数据库一致；索引使用独立有效语句，不混用其他方言。
- 每个写操作明确幂等与并发语义，不一律套分布式锁。
- Agent 编排、Prompt、工具预算交给 `$haonan-s005-3-lld-agent`；后端只定义可调用工具的服务契约与执行边界。
- 方案是 `CREATED`，只有从代码、测试或运行结果观察到的事实才是 `OBSERVED/VERIFIED`。

## 交接

向 `$haonan-s005-3-lld-agent` 提供工具/API/超时/权限契约，向 `$haonan-s005-4-lld-front` 提供接口/流式/错误/恢复契约，向 `$haonan-s009-test`/`$haonan-s010-safety` 提供可测量的验收和安全边界。
