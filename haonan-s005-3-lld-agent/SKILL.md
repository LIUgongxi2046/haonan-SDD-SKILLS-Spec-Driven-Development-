# Haonan S005-3 Agent 详细设计

## 模式与输入

`DESIGN` 定义能力与运行过程，`AUDIT` 核查现有执行与采用路径，`MIGRATION` 规划模型、Prompt、工具和知识版本变化。

读取目标、需求、数据及后端规范、交互、风险和预算，检查当前 Harness 实际提供的工具和能力。不假定存在 Hook、MCP、并发代理或特定审批工具。模型能力、API、价格和限制变化时核查当前官方资料。

## 能力映射

每项承诺记录：业务目标、用户入口、输入身份、实际 provider/model、Prompt 版本、工具实现、知识来源、输出结构、采用动作、业务结果及检查方式。

Agent、Skill、Tool 的目录登记与适配器实际执行分别验证。配置发布需说明运行时读取的版本和范围；存在另一套预置配置时，检查界面设置是否真正影响运行。连接成功、产生文本、建议可用和完成业务动作分别记录。

## 执行设计

1. 确定是否需要模型或 Agent，保留满足完整需求的确定性处理方式。
2. 定义计划、执行、等待、审核、完成、失败、取消状态，每个终态有可核查条件。
3. 明确上下文来源、最小字段、时间范围、版本、检索、压缩和失效。操作者、角色及业务对象在请求、工具、回复、跳转和采用时一致。
4. 为工具定义目的、Schema、权限、资源范围、幂等、超时、错误、结果与审计；写入严格遵循用户和业务授权。
5. 设定轮次、时间、Token/成本、并发与重试预算，检测无进展，失败保持可观察，禁止替代模型结果伪装目标模型成功。
6. 明确人工审核是否适用、依据及用户完成审核的入口；批准记录与实际执行结果分别验证。
7. 将结果采用到业务的过程纳入设计：引用、字段映射、用户确认、服务端校验、写入或只读调阅，以及重复采用处理。
8. 知识更新、删除、引用与模型调用证据可追溯；不存储或展示内部推理过程。

详细字段见 [Agent 规范](references/agent-contract.md)。

## 模型部署与质量

- `HOSTED_API`：核对端点、凭据状态、模型 ID、实际请求、输出及数据处理范围；不要求获取供应商内部模型文件或 GPU 信息。
- `SELF_HOSTED`：增加制品校验和、引擎、量化、资源和部署版本验证。

按业务风险设计功能验收、AI Evals、安全评测和发布条件。阈值和附加门槛具有来源与适用环境，不能把所有建议固定为用户必须完成的步骤。效果尚未评测时准确说明，功能尚未实现时继续保留任务。
