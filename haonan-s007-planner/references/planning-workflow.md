# 完整任务规划与执行交接

读取用户要求、PRD/AC、设计、原型、评审问题、当前代码、测试和未提交改动。代码用于确定现状，目标范围由用户决定和批准需求确定。

## 完整范围

1. 建立原始承诺集合：每项包含来源、稳定 ID、用户结果、适用角色和平台。不能只从已有 routes/API/数据库表生成需求分母。
2. 将每项结果具体化为验收动作：入口、前置、输入、操作、预期结果、后续使用和适用状态。尚无页面的需求仍须登记。
3. 把验收动作映射到任务；检查没有任务负责、没有验收、重复覆盖但核心结果缺失的条目。
4. 保留用户最新约束：限定页面、复用风格、允许的模拟范围、禁止修改区、平台及外部操作授权。读取允许的窗口或 Agent 数量、模型、工具和工作目录，复用已有有效责任。S007 形成协作计划，不因编写计划自动创建窗口或启动执行；窗口、模型与并行数量按实际授权填写，不固定在通用 Skill 中。
5. `REPLAN` 核对所有未验收 ID。排除承诺必须引用用户范围决定，说明修正或更换任务名称不能关闭原始业务需求。
6. 接收 S006 的适用评审版本、范围、决议及未关闭问题，逐项建立 `issue_id → task_id → 修复产物 → 复核检查与证据` 的关联。评审附带条件明确阻塞哪些动作及解除责任；`REVISE` 对应设计修订与复核任务，其他依据充分的工作继续。设计修改交给所属专业技能维护，S007 保留调度和追踪责任。关闭问题须依据对应复核结果，不能用创建工单或补充说明代替原要求的修复。已关闭问题核验版本后继承；适用性按实际范围判断，不为局部任务自动增加完整评审。

跨会话任务使用 [交付记录](../../haonan-s000-pmp/references/delivery-ledger.md)，任务字段见 [任务模板](task-template.md)。JSON 计划或既有任务系统导出的当前 JSON 快照使用 S000 的 `scripts/validate_delivery.py` 校验；S007 负责定义映射，当前执行者更新原系统后重新导出。小型单项正文计划人工核对同样关系，不将正文传入 JSON 校验器。工具验证显式映射，需求内容的完整性仍需 S006 审查。

## 任务与依赖

S000 向 S007 提供当前项目目录及版本、实际主 Agent 与执行者、用户暂停或恢复决定、全部未完成范围、现有证据和待处理问题。S007 仅维护当前任务来源中的计划关系，实施启动由实际授权决定。对有待采用的规则，核查其项目采用位置、执行任务、实际工具入口及支持依据；必要能力未具备时安排配套任务并登记使用方和接收检查。原型、资源、模型和窗口要求以项目事实为准，不将特定项目编号或工具名称固定为通用要求。

- 按连贯用户结果组织任务；共享模块和技术前置可以独立实施，但模块完成须覆盖完整业务流程。每项业务结果有唯一执行负责人，负责全部适用层次；明确子任务委派时保留父功能责任。协调负责人即主 Agent，业务执行负责人即子 Agent，在计划中登记各自实际窗口名称、会话或 Agent ID 和所属任务。主 Agent 沿用用户指定或已生效的协调负责人，负责分配、指导、监督、处理优先级、依赖、共享修改及责任转移；集成验收负责人验证组合后的功能，主 Agent 负责整体接收。单执行者可以兼任。
- 为任务记录 `acceptance_ids`、`depends_on`、允许修改范围、风险、验证命令、阻塞条件和责任技能。
- 区分实现依赖、验证前置、外部联调和发布依赖；外部凭据或设备未提供时，项目内部可执行工作继续推进。逐项列出可同时执行的任务和开始条件，前置产物明确到版本、接收者和验证入口；条件未满足时只暂停依赖它的动作，其他获准工作继续。
- 写出数据产出方、实际使用方、读取或触发时机、业务终态。配置能保存与配置会生效分别验收。
- 接口和 Schema 变更包含兼容、迁移与数据保护；高风险任务包含恢复方法。共享修改请求登记所需产物、业务依据、受影响使用方、负责人和接收条件。负责人交付后，由接收者核实当前版本及实际消费。请求不自动扩大执行者写入范围。
- 并发任务检查共享文件、数据库、进程、端口和生成物的归属。文件、Schema、迁移、索引、生成物、数据库、服务、进程、端口分别指定唯一写入者。不同工作目录仍核实外部共享资源。没有隔离证据的冲突动作顺序执行，禁止多个执行者同时接管同一资源。
- 只纳入用户授权范围；不追加无关重构、框架升级或菜单。

业务功能的 Data、Backend、Agent、Frontend、Integration 子任务保留全部适用内容，各自关联父功能、原始验收 ID、负责人及产物。父功能指定完整用户结果和集成验收者，子任务局部通过不能代替组合验收。共享技术前置独立安排时，明确其使用方和交付条件。

以可独立验证的业务结果分配开发责任，登记相关菜单、页面及跨页面操作；菜单数量不决定任务数量。每项功能覆盖用户入口、适用的数据与接口、业务处理、前端呈现、结果重读或后续使用及异常路径。前后端输入明确时可以在同一功能内并行，多个独立功能也可按资源条件并行，但每项功能都有持续负责其开发集成的执行者。禁止将全部页面与全部接口作为两个互不集成的长期队列，等待项目末期统一联调。

主 Agent 在现有任务来源登记已开始且尚未通过开发集成验证的功能集合、数量上限、各功能负责人、当前可执行集成、剩余断言及阻塞。默认每名功能负责人同时负责一个此类功能，总量不超过已授权且实际可用的功能负责人数量；专门承担共享前置工作的执行者不自动增加可并行功能数量。同一功能的多个技术子任务只计为一个功能，已经通过开发集成但等待 S009 的功能单独统计。阻塞功能继续计入未集成功能集合，不能通过改名、暂停或转交使其从记录消失。

派发新功能前检查已有功能的集成条件。能够继续的集成、修复及必要依赖优先安排；达到上限时不直接追加新的功能。确因外部阻塞或资源分工需要调整数量时，主 Agent 记录受阻事实、保留的功能责任、新功能执行者、集成接收能力、调整后的上限和下次检查时间，在原授权及共享写入规则内执行。不得仅以执行者空闲为由持续增加未集成功能。未达到上限、没有挤占可执行集成且依赖满足时，可以推进独立功能，不能将整项目强制串行。

每个前置任务的独立交付检查仅依赖已有输入及本任务产物；需要后续功能才能执行的检查归属对应集成或最终验收任务，原始业务验收要求完整保留。使用当前共享校验器时，`depends_on` 中的任务必须先达到 `ACCEPTED`；部分产物需要提前交付时，为其安排可独立验收的技术任务，不修改整个前置任务的完成事实。计划同时核查代码产出依赖与验收执行依赖，不能只检查任务 ID 图无循环而忽略验收动作依赖后续功能。父功能等待子任务及独立测试，子任务不等待父功能最终完成。

## DoD

完成条件描述可观察业务结果及检查方法。例如配置修改后，业务操作读取指定生效版本，产生对应结果；导出文件可读取，内容对应批准的数据范围。只读功能验证查询结果、来源、权限和新鲜度，不强制添加写操作。

编译、路由、按钮存在、接口拒绝请求等各有检查价值，不能单独替代业务验收。原型、模拟、真实接入和未提供外部依赖分别登记。说明类修复只关闭说明类任务。

任务大小由职责、依赖和连贯验收决定，不限制固定文件数或步骤数。细分后的每项保留原始验收 ID，父任务仍负责组合结果。

前端 DoD 关联批准页面映射、原型版本、源码、CSS、Token、资源、视口与全部交互状态。项目要求原型 1:1 还原时，逐页列明结构、样式、控件、状态、响应式与实际接口消费的检查。视觉工具按授权使用，未执行时保留未验收事实，不以行为通过推断视觉通过。

高保真页面从实施开始使用批准原型的结构、CSS、Token、图标和资源；组件化与数据绑定保留原设计的尺寸、排列和交互。公共导航、页面容器、表格、表单等在扩展至多个页面前，由唯一负责人在适用页面环境、视口和状态下完成检查，记录原型版本、组件版本和接收证据。不同页面族使用条件不同的，分别检查对应条件，不能用一个页面通过推断全部页面均通过。

每页安排结构与样式形成后的核对、业务绑定后的核对及交付接收。内容长度、加载、空白、失败、权限、弹窗及响应式等适用状态从开发过程中验证，不累计为全部功能完成后的页面重做。发现差异在当前任务内修正并核查受影响范围；公共组件存在已知差异时暂停其扩展复用，其他不受影响的工作继续。交付复用仍有效的阶段证据，只补充变化及未解决部分的检查。

上述检查由执行者、主 Agent 或指定接收者完成，沿用用户已有设计与工具授权，不新增逐页用户确认。视觉比较未获准时执行源码、DOM、计算样式及行为检查，视觉部分明确记录未执行；不得自动调用视觉工具或将非视觉结果表述为视觉一致。原型变化按实际影响维护当前依据与页面检查，不能擅自改变设计以满足现有实现。

开发窗口执行当前修改直接相关的检查，交接满足全部必需验收。完整工程批次由指定负责人执行，各窗口提供所需产物与有效证据。联调明确协议、代码、依赖、配置、数据版本、服务负责人和完整检查清单，执行期间不改变批次输入；必要变更结束当前批次后登记新版本并复验受影响检查，隔离的其他获准工作可以继续。S009 启动条件遵守用户和项目决定。

页面比较条件在实施前明确到批准原型、浏览器、视口、缩放、适用设备像素比、字体及资源版本、数据内容和交互状态。动态内容的处理不得隐藏需要验收的业务区域；结构、行为、视觉检查分别有 ID、责任阶段和结果。沿用有效项目级视觉授权及其范围，权限未具备时保留 `VISUAL: NOT_RUN`，不要求用户逐页确认，也不降低页面最终验收条件。已授权的图像比较检查完整页面及适用状态，差异指标仅辅助定位，不能单独证明完整还原。

验证计划按 `check_id` 记录检查定义、需求依据、全部必要输入、直接及间接依赖、环境与数据身份、实际使用方和失效条件。版本变化后逐项判断影响，不仅按目录或提交名称判断。相同输入、环境和检查定义的共同检查由唯一执行者运行，其他任务引用有效证据并执行自身专属断言；检查副作用、隔离要求或独立执行责任不同的，不能合并。项目要求的当前完整验收及 S009 独立执行仍须安排。

## 委派与持续执行交接

计划分别列出 S008 实现及开发验证任务、S009 独立测试任务与父功能最终验收。S008 开发任务的 `ACCEPTED` 只对应其明确的交付检查和记录，S009 未执行的检查保持 `NOT_RUN`；父功能最终验收继续等待这些检查。原始业务结果与验收 ID 保持稳定，阶段检查使用可追踪的独立 ID，不能用调整任务归属取消测试要求。

用户要求全部开发完成后启动 S009 时，计划列出本批全部 S008 开发任务 ID、必须通过的开发及集成检查、开发记录、待测试版本、环境、适用评审条件和接收负责人。主 Agent 核验这批开发交付完成且相应写入已结束后，在已有测试授权内启动 S009，不等待 S009 自身的通过结果。生产接入、视觉检查等项目按用户授权与阶段归属分别保留状态；明确归属于后续阶段或当前未授权范围的检查不自动成为本批启动条件，已明确属于开发交付的必需检查仍须满足，未执行项目不能宣告通过。仅有部分开发任务完成不满足整批启动条件。

S009 从批准需求独立核对预期结果，接收需求和验收映射、代码与制品版本、环境与数据版本、用例入口、开发证据、已知问题及未运行项。测试缺陷由主 Agent 分配给 S008 的责任执行者，修复与相关开发检查完成后交回 S009；S009 复验失败项及受影响范围，关联缺陷 ID、修复版本和证据，复验通过后关闭对应缺陷。用户规定的整批开发前置适用于首次启动，已启动测试中的授权修复按缺陷循环处理。S006 按已授权范围复核评审条件和最终交付结论，主 Agent 不能用自身完成声明代替必要的独立测试或复核。

联调前核查证据工具的实际能力。当前共享校验器只接收与当前基线 ID 一致且输入仍有效的执行回执；同基线无关改动经过依赖核查后可复用有效结果。基线改变时保留原回执，按当前工具要求在新基线执行所需检查，不能改写原回执的基线、时间或结果，也不能通过保持失真的基线描述取得通过。跨基线适用性复核的配套设计见 [S000 证据复用配套设计](../../haonan-s000-pmp/references/evidence-reuse-design.md)，该能力须完成工具实现与验证后才能使用；本计划不能据文字约定宣称工具已经支持。

计划为 S008 与 S009 提供同一检查影响依据。实际受影响的检查标记 `STALE` 并复验；未受影响且满足工具条件的证据可以复用。跨基线能力尚未具备时，分别说明业务影响结论和工具要求的新执行，不能误报已实现复用。复核优先读取现有版本差异、输入清单和使用关系；依据不足时执行覆盖不确定范围的检查，不反复生成相同分析说明。进入 S009 或出现新 commit 本身不构成业务上全部失效的依据，当前工具限制仍须遵守。

只有授权允许委派时，由主 Agent 向登记的子 Agent 下发子任务，包含需求来源、验收动作、修改边界、依赖、禁止缩减项和证据要求，并说明实施依据、已知问题和汇报入口。子 Agent 确认任务与输入后执行，返回文件或 `OK` 只说明局部操作结果，主 Agent 读取产物并确认指定集成验收者已验证整合后的业务行为。子 Agent 的提交属于待接收结果，整体完成由主 Agent 根据有效证据判断。

向 S008 交付完整 backlog、当前可执行项与已授权执行模式。用户要求全部完成时，单项结束后继续下一项，不把逐项授权作为默认流程。

协作启动条件包含实际 Agent ID、状态查询和消息入口、运行操作观察方式、继续任务及会话续接能力；主 Agent 在获准执行时用可用工具核实，不因编写计划启动执行者。复用既有协作工具和任务来源，不额外建设监督系统。未具备的能力登记限制及处理责任，不能以定时文字承诺代替实际运行。

主 Agent 在子 Agent 接收任务、提交阶段产物、报告阻塞和申请交付时检查进展；执行中使用可用的进度或状态工具持续跟踪，并在关键阶段核实代码、验证结果与剩余断言。指导必须明确问题、设计依据、解决方案或定位步骤、负责人和完成条件。涉及共享规范或多个任务时，通知所有受影响子 Agent 并确认其读取生效版本；子 Agent 实施后回报证据，主 Agent 核验问题已解决。没有新增信息时不重复索取同一报告，也不重复运行输入未变化且仍有效的检查。

任务接收时，由主 Agent 根据依赖和运行方式确定阶段预期结果、预计交付时间及监督检查间隔，登记带时区的下次检查时间。项目已有规定直接继承；缺少规定时，执行期间默认每 15 分钟检查一次可用状态，阶段产物、失败或阻塞消息到达时及时处理。主 Agent 可以根据实际执行证据调整间隔并登记依据，不能仅因没有结果不断延后检查。子 Agent 运行长时间命令前说明命令或作业标识、可观察状态和预期产物；检查时读取已有运行状态，不为催报而终止正常操作。状态没有变化时无需重复发送长报告或读取完整历史。

检查时间到达却没有反馈时，主 Agent 主动核查执行者状态、最近产物和运行中操作；确认执行者空闲且任务未完成时发送明确的继续任务或指导。无法确认是否仍在写入时保留原写入责任，查明状态后按交接规则安排接管；不能启动第二个执行者修改同一范围。运行环境不支持持续监督或恢复执行时如实记录能力限制与未完成项，不声称已安排后台监督。预计交付时间到达但产物缺失时立即检查原因、剩余断言及下一动作，不等待形成两轮回报。

监督记录保留最近实际检查时间、状态或产物依据、处理动作、负责人、预期证据和下次检查时间，可以直接引用工具结果，无需复制完整历史。阶段交付、失败和阻塞消息及时处理，时间检查补充发现遗漏。发送提醒或继续任务仅代表动作已发出，问题关闭需要对应执行证据。会话续接恢复全部未完成任务、运行操作和已到期检查；尚有可执行授权任务时，进度报告不构成监督结束条件。

子 Agent 在分配范围内完成实施、针对性验证、修复和记录，遇到跨任务依赖、共享写入冲突或无法解决的问题时向主 Agent 回报事实、已检查内容、影响范围和所需协助，同时继续条件满足的部分。子 Agent 不自行改变其他执行者的责任、扩大任务范围或新增下级执行者。主 Agent 优先通过明确指导和责任协调解决问题；需要亲自修改时先完成写入责任交接。主 Agent 持续跟踪至全部获准任务完成或用户停止，仅在授权、范围或必要输入确需用户决定时请求用户处理。

多窗口任务交接同时包含责任、当前实现、文件范围、代码与输入版本、当前环境、有效证据、完整未完成项、剩余断言、阻塞、接收者和接收条件。转移责任时，原执行者停止对应写入，接收者确认后生效，再维护现有计划中的责任。各执行者按已分配责任连续推进，协调负责人维护全部承诺的覆盖，禁止重复领取其他执行者正在负责的任务。

协作安排同时明确暂停决定的传达入口、运行操作及服务负责人、停止核验和恢复接收条件，具体执行遵守 [S000 状态与授权](../../haonan-s000-pmp/references/delivery-workflow.md)。停止处理与任务完成分别记录，不因暂停关闭原始验收。恢复时使用当前任务与责任，已取消工单和旧排队指令不得重新派发。

每轮报告新增可操作功能、通过的业务验收、解除的阻塞和当前版本证据。连续两个预定进展检查时点没有新增业务验收、经过验证的阶段业务结果、必要前置产物或阻塞解除时，主 Agent 检查重复读取、重复验证、失败原因、依赖和责任分配。新增代码、文档、测试文件或运行次数本身不能解除此检查条件。必要前置产物须关联原始验收及实际使用方，并具有通过的检查；没有验收含义的文件增加不计作阶段结果。

触发检查后，主 Agent 根据当前证据明确原因或待验证假设、处理者、下一项定位或修复动作、预期证据及下次检查时间，监督动作执行与结果。正常长时间操作可以依据运行进展继续；需要调整实现方法、依赖顺序或责任时保留全部原始验收，责任变化遵守交接要求。检查次数本身不能作为失败依据，必要验证必须保留；监督时间只触发检查，不自动终止任务或增加未经用户规定的费用、时间限制。

跨任务问题按 [S000 持续交付流程](../../haonan-s000-pmp/references/delivery-workflow.md) 分配和接收，S007 将有效决定写入原工单，不另建监督任务表。问题处理记录应能回答：哪项事实触发处理、当前安排如何变化、谁执行、谁接收、什么证据证明解除。没有改变安排的检查可以记录继续依据；不能为展示监督动作而制造计划变化。S008 回报实际消费和验证结果后，主 Agent 核验计划中的阻塞解除条件，未满足时保留全部受影响任务。

## 输出与检查

输出完整需求覆盖表、任务 DAG、验收动作、执行顺序、阻塞项及授权边界。检查 ID 唯一、依赖存在且无循环、承诺有验收、验收有责任任务。计划任务使用 `TODO`，只有符合当前证据条件的实施任务才使用 `ACCEPTED`。不根据历史完成声明直接沿用当前通过状态。

同时核查业务负责人、共享资源唯一写入者和集成验收负责人均明确，可并行任务不存在未经处理的写入冲突，前置产物有人交付、接收条件可验证。责任和协作信息维护于现有计划，任务状态保持唯一来源。计划中的执行者分配与实际启动、已完成交接分别记录，不将计划动作报告为已执行结果。

进度统计沿用项目已有且可核查的计算方法；缺少方法时，业务验收比例 = 当前范围内全部必需验收通过的业务结果数量 ÷ 当前批准业务结果总数。分母使用稳定业务结果 ID，保留未开始、阻塞和待验收项；子任务增加或合并不改变分母，父子任务不重复计数。比例描述业务结果的验收数量，不推断剩余工时或工作量。已实现待验收数量、阶段产物和技术任务状态单独列明；分母为零或范围尚未确定时不报告百分比。范围变化依据用户决定更新范围版本并解释可比范围，不能为提高比例调整统计单位或权重。

授权模拟环境的业务验收与生产接入分别统计，报告环境及能力类型，不能混合为整体生产完成率。每次报告包含统计时间、范围版本、分子与分母、相较上次新增或失效的验收 ID，以及证据来源；证据失效时相应结果退出通过分子并说明当前待复验项。统计从唯一任务来源生成，不额外维护另一套完成状态。

阶段报告将同一统计时段的新增业务结果、必要前置产物和阻塞处理与消耗关联：记录起止时间及经过时长；工具可提供用量时记录主 Agent 与各子 Agent 的 Token 增量、来源、覆盖范围和输入、输出、缓存等可用分类。累计计数需使用本期起止值计算差值，主 Agent 汇总已包含的子 Agent 用量不得重复相加；无法区分任务时仅报告会话或窗口范围，不推算任务用量。工具不提供用量时记录不可取得，不能估算为精确值或填零。并行窗口时长不能相加冒充项目经过时长。使用现有工具和记录取得这些信息，不为统计增加无关系统；只在可靠费用来源存在时报告金额，费用与时间上限沿用用户规定。持续消耗但没有对应阶段结果时执行上述原因检查，不能通过降低质量或缩减范围改善数字。
