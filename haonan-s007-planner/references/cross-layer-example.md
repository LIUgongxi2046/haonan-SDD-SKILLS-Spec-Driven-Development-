# 跨层开发工单示例

当功能同时涉及受保护的数据、模型处理和交互界面时，可参考以下工单的验收写法。技术、数据权限和阶段要求以当前产品设计为准。

### 🎫 Task 1: [Data 层] 图谱存储模型搭建
- **📍 动作意图**：确立底层物理边界，为后续算法提供存储基础。
- **📥 必需上下文**：`@S005-1-lld-data.md`。
- **📝 实施细则**：
  1. 在图数据库 (Neo4j) 或关系型 DB 中构建 `DiagnosticNode` 与 `EvidenceLink` 的实体 Schema。
  2. 运行本地 Migration 生成结构。
- **🛑 验收门禁 (DoD)**：Schema 成功编译，本地数据库实例可见对应表结构。
- **协作交付**：迁移由指定负责人写入；向 Task 2 提供结构、约束、迁移版本及实际读取证据。

### 🎫 Task 2: [Backend 层] 节点提取 API 与 Hook 控制
- **📍 动作意图**：封装数据访问层，建立脱敏拦截机制。
- **📥 必需上下文**：Task 1 产物, `@S004-hld.md`, `@S005-2-lld-back.md`。
- **📝 实施细则**：
  1. 使用获准测试环境与真实记录编写 BDD，分别验证合法访问及无权限访问。
  2. 实现后端的 `PreToolUse` PHI 数据脱敏 Hook 拦截器。
  3. 暴露供 Agent 调用的内部写库 API。
- **验收条件 (DoD)**：合法请求能够完成操作、持久化后重新读取一致，无权限请求被拒绝；记录实际命令、断言、原始结果与环境。
- **协作交付**：向 Task 3 提供接口、权限、错误和数据语义的有效版本；共享规范由所属负责人更新并通知使用方。

### 🎫 Task 3: [Agent 算法层] 诊断思维推理链编排
- **📍 动作意图**：构建 AI 推理能力，确保其行为严格限制在可用工具内。
- **📥 必需上下文**：Task 2 API, `@S005-3-lld-agent.md`, `@S002-prd.md`。
- **📝 实施细则**：
  1. 定义当前产品内业务 Agent 的 System Prompt 与 Prompt Cache 前缀，沿用 LLD 中的角色名称与 identifier。
  2. 使用 LangGraph 定义状态机节点：解析病历 -> 验证置信度 -> 调用 Task 2 的 API 入库。
  3. 编写核心算法流转的单元测试。
- **验收条件 (DoD)**：按批准环境使用模型与工具处理获准资料，输出通过 Schema 校验，验证 Task 2 写入和持久化重读、来源引用、运行事件及失败行为。真实模型与工具的调用要求在对应真实接入验收中保留；授权模拟结果标明能力类型。此项检查验证交给 Task 5 的产物，后续 UI 实际使用由 Task 5 验证并关联同一原始业务验收，不能只用控制台 JSON 宣告父功能完成。
- **协作交付**：向 Task 5 提供运行与事件语义、输出 Schema、来源引用、状态及失败行为的证据。

### 🎫 Task 4: [Frontend 层] 思维导图画板 UI 重构
- **📍 动作意图**：分离逻辑，完整进行 UI 的像素级还原。
- **📥 必需上下文**：`@S003-prototype.md`, `@S005-4-lld-front.md`, `diagnostic-map.png`。
- **📝 实施细则**：
  1. **视觉依据**：读取批准的界面规格和 Token；视觉工具获准时比较对应截图。
  2. **组件编写**：使用 Tailwind 和规定的语义化 Token 复刻节点卡片骨架。
  3. **开发中核对**：公共画板布局与节点卡片向更多页面复用前，完成对应原型结构、样式及适用状态检查；每页形成结构与样式后立即核对并修正，绑定实际业务后检查内容长度、状态及交互引起的布局变化。检查证据与差异处理保存在原任务记录。
- **验收条件 (DoD)**：节点、状态、操作、Token 与确认设计一致，完成适用视口和交互检查；视觉比较未执行时不得给出相似度或通过结论。
- **协作交付**：向 Task 5 提供页面映射、原型版本、组件入口、状态和操作绑定位置；公共组件修改通过唯一写入者交付。
- **接收条件**：所需设计与组件输入已满足且无共享写入冲突时可独立执行；Task 3 的完成状态仅在存在实际输入依赖时作为前置。组件交付检查与 Task 5 的实际接口消费分别登记，页面完整验收仍须覆盖两者。

### 🎫 Task 5: [Integration] 流式接收与状态机集成
- **📍 动作意图**：完成数据、后端、Agent 与前端的完整业务连接。
- **📥 必需上下文**：全套前序代码，`@FrontendStore.ts`。
- **📝 实施细则**：
  1. 将 Task 4 中的 Mock 数据替换为当前授权环境的正式接口消费；用户明确授权模拟服务时，按批准模拟适配器执行并标明环境，生产接入分别验收。
  2. 订阅 Zustand 状态机，挂载 Task 3 输出的 SSE 算法流，实现思维导图的动态增量渲染。
- **验收条件 (DoD)**：实际点击解析，验证请求对象、模型调用、节点数据、来源引用、持久化重读与后续使用；覆盖刷新、重复点击、对象切换和失败状态。本任务负责的开发组合检查通过后接收其交付；对应父功能须在开发检查及全部适用独立验收通过后才能完成。
- **集成责任**：由父功能指定的集成验收者，在明确的代码、接口、配置和数据版本上执行全部必需检查。各子任务的局部通过不能替代父功能验收。
- **后续测试**：本项承担开发期间的组合验证。S009 按计划独立核验需求、异常路径和质量指标；父功能最终完成须满足全部适用验收，S008 开发检查通过不代表 S009 已通过。示例依赖为 Task 1 → Task 2 → Task 3，Task 4 按自身输入执行，Task 3 与 Task 4 的交付产物共同进入 Task 5。
