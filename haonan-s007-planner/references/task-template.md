# 实施任务字段

完整范围与状态使用 [交付记录](../../haonan-s000-pmp/references/delivery-ledger.md)。每个任务保留以下信息，按实际任务组织表格或结构化记录。

| 字段 | 要求 |
|---|---|
| `task_id` | 稳定且唯一 |
| `development_record` | 本项 S008 任务唯一 Markdown 路径；复用已有合规记录或指定项目内路径，索引关联同一任务 ID |
| 相关开发记录 | 检索命中、当前核实依据、受影响文档及维护责任 |
| 需求来源 | 原始承诺 ID、用户决定、批准需求 |
| 必需上下文 | 实际 PRD、HLD、相关 LLD、前置产物、接口、数据版本、UI Token 和获准参考的具体路径 |
| `acceptance_ids` | 本任务负责的全部验收动作 |
| 用户结果 | 角色、入口、操作、可观察结果 |
| `depends_on` | 必须先通过独立交付检查并达到 `ACCEPTED` 的前置任务 ID；实现、组合验收、外部和发布条件分别解释，不能形成子任务与父功能相互等待 |
| 决策依赖 | 当前 `decision_id`、状态、影响动作和解除条件；继承已有确认 |
| 评审承接 | S006 报告路径、版本、范围、决议、相关 `issue_id`、责任任务、受影响动作、修复产物、复核者及关闭证据；不适用时说明依据 |
| 修改范围 | 允许目录、共享文件归属、禁止改动及用户已有变更 |
| 实施内容 | 满足完整结果的必要步骤，数量由实际工作决定 |
| 业务衔接 | 产出方、使用方、版本、生效时机或合法终态 |
| 验收方法 | 实际操作、预期结果、检查 ID、命令、数据来源及环境 |
| 风险与恢复 | 接口兼容、迁移、权限、幂等和恢复方法 |
| 状态与阻塞 | 任务状态、证据状态、原因、已检查内容和解除条件 |
| 交接 | 当前产物、完整未完成项和下一可执行任务 |
| 父功能与子任务 | 原始业务结果、父任务 ID、子任务 ID 和验收 ID 的关联；父任务承担组合验收 |
| 功能推进安排 | 菜单或页面入口与完整业务结果的映射，适用层次、开发集成负责人、前置产物和检查入口；当前未完成开发集成的功能集合、数量上限、阻塞及调整依据 |
| 执行负责人 | 当前负责完整业务结果或明确子任务的子 Agent，填写实际窗口名称、会话或 Agent ID、所属主 Agent、任务 ID 和接收状态；单执行者可兼任 |
| 协调与集成责任 | 协调负责人即唯一主 Agent，填写实际窗口名称、会话或 Agent ID、指定依据及责任生效状态；同时填写集成验收负责人。主 Agent 负责分配、指导、监督、解决问题和整体接收 |
| 监督与反馈 | 任务接收、阶段产物、阻塞和交付的回报入口；检查间隔、下次检查时间与时区、最近有效反馈、未收到反馈时的核查动作；主 Agent 的指导、处理负责人、生效版本、执行确认和结果证据 |
| 监督执行条件 | 实际 Agent ID、可用状态与消息入口、运行操作标识、继续任务与续接方式、最近检查时间和依据；能力未具备时保留限制，安排与实际执行分别记录 |
| 阶段预期结果 | 对应业务结果、验收 ID 或必要前置产物、可执行检查、预计交付时间、当前剩余断言；阶段完成不改变父功能的全部验收范围 |
| 进度计算依据 | 引用项目唯一统计来源，填写范围版本、稳定业务结果 ID 集合、环境、分子、分母及计算方法；任务数量与实现状态另行报告，不能代替业务验收比例 |
| 阶段消耗 | 本期起止时间、经过时长、可取得的各执行者 Token 增量、来源及统计覆盖范围，关联新增业务结果、证据和解除的阻塞；未知用量记录不可取得，不能填零 |
| 可并行任务 | 可同时执行的任务 ID、前置条件、允许并行的范围和无写入冲突的依据 |
| 前置产物与接收 | 产出任务、所需产物及版本、接收者、满足条件和验证入口 |
| 共享资源写入责任 | 文件、规范、迁移、索引、生成物及共享配置的唯一写入者和使用方，可引用计划中的集中登记 |
| 环境责任 | 工作目录、数据库、服务、进程、端口和维护者，记录隔离依据；不适用项说明事实 |
| 页面验收依据 | 页面映射、原型版本、源码、CSS、资源、Token、视口与状态；项目要求 1:1 还原时列出对应检查 |
| 页面开发中检查 | 公共布局与组件复用前、页面结构与样式形成后、业务绑定后及交付时的检查负责人、适用视口与状态、组件版本、实际证据、未解决差异和受影响页面；复用检查注明有效依据 |
| 页面比较条件 | 浏览器、视口、缩放、适用设备像素比、字体与资源版本、数据与交互状态、动态内容处理及授权来源；结构、行为、视觉检查 ID 和责任阶段分别登记 |
| 验证分工 | 开发期间直接相关检查、交接全部必需验收、完整工程批次负责人及证据复用条件 |
| 验收阶段与测试接收 | S008 开发交付、组合验证、S009 独立测试及最终验收的任务和检查 ID；S009 启动条件、接收者、版本及环境、待执行矩阵、缺陷返回与复验责任 |
| 证据复用条件 | 当前基线、原始回执及输入范围、使用关系、工具版本和能力；同基线复用条件与跨基线适用性复核分别登记，不修改原执行回执 |
| 检查影响范围 | 每项 `check_id` 的验收与检查定义、源码和测试、直接及间接依赖、构建输入、配置、环境和数据身份，关联实际使用方；记录变更依据、失效条件、复验或复用理由及不确定范围 |
| 共同检查与独立执行 | 可共享检查的唯一执行者、实际输入与适用范围、证据引用和任务专属断言；S009 必须独立执行及用户要求当前执行的检查单独标明，不以阶段名称自动增加全部重跑 |
| 交接版本与生效条件 | 代码、接口、环境和数据版本，当前有效证据、接收者、剩余断言及阻塞负责人；责任转移注明原执行者停止写入和接收确认 |

既有字段共同承载主 Agent 的指导与接收：在“状态与阻塞”引用触发处理的事实，在“实施内容”明确下一动作，在“执行负责人”和“前置产物与接收”明确处理者及接收者，在“监督与反馈”引用执行确认、预期证据、核验结果与下一检查时间。公共工具能力与规则采用依据可以集中记录并引用，必要配套任务沿用相同字段。没有新增事实时引用已有记录，不为同一问题增加重复工单或第二份完成状态。

每项 S008 任务的完成条件包含 [开发记录](../../haonan-s000-pmp/references/task-development-records.md) 和索引核查。字段表用于工单及索引；写入现有 JSON 交付记录时遵循其 Schema，不加入未定义属性。

任务依赖无循环，所有承诺均有责任任务。共享前置任务可以独立完成；组合后的模块需要完整验收。子任务回报文件或 `OK` 后，主任务读取产物并验证集成结果。

原始业务验收 ID 保持稳定，开发交付与 S009 独立测试的检查分别映射到该业务结果。需要独立验收前置产物时建立相应技术交付验收，不把父功能全部验收复制为每个子任务的完成前提。已有映射调整时保留完整承诺及有效证据引用，由主 Agent 核验范围；父功能最终结果继续等待全部适用检查。

依赖检查记录前置任务、所需产物及版本、接收任务、满足条件和验证入口。实现前置、运行验收条件与发布条件分别判断：尚未取得生产发布条件，不自动阻塞获准的本地开发；缺少必要接口语义时暂停依赖它的实现。共享文件、索引、环境和数据库明确维护责任；没有委派授权时由当前执行者按依赖完成，不自动创建其他会话。

协作字段维护于现有任务计划，公共责任信息可以集中登记并由各工单引用。主 Agent 与协调负责人使用同一身份登记，子 Agent 与执行负责人使用同一身份登记；每项任务必须能定位到实际执行者和监督者。单执行者填写相同的责任关系，不要求额外创建窗口、数据库或任务系统。索引保留检索职责，任务状态继续使用唯一来源。

范围调整必须有用户决定，不能通过改写 DoD、说明或任务名称关闭尚未实现的功能。
