# Haonan S007 实施任务规划

## 工作模式

- `SLICE`：为明确功能或缺陷安排完整实现与验证。
- `BACKLOG`：为已确认范围建立全部任务、依赖与验收。
- `REPLAN`：根据真实进展和用户决定更新待办，保留尚未验收的原始承诺。

读取用户要求、PRD/AC、设计、原型、评审问题、当前代码、测试和未提交改动。代码用于确定现状，目标范围由用户决定和批准需求确定。

## 完整范围

1. 建立原始承诺集合：每项包含来源、稳定 ID、用户结果、适用角色和平台。不能只从已有 routes/API/数据库表生成需求分母。
2. 将每项结果具体化为验收动作：入口、前置、输入、操作、预期结果、后续使用和适用状态。尚无页面的需求仍须登记。
3. 把验收动作映射到任务；检查没有任务负责、没有验收、重复覆盖但核心结果缺失的条目。
4. 保留用户最新约束：限定页面、复用风格、允许的模拟范围、禁止修改区、平台及外部操作授权。
5. `REPLAN` 核对所有未验收 ID。排除承诺必须引用用户范围决定，说明修正或更换任务名称不能关闭原始业务需求。

跨会话任务使用 [交付记录](../haonan-s000-pmp/references/delivery-ledger.md)，任务字段见 [任务模板](references/task-template.md)。JSON 计划或既有任务系统导出的当前 JSON 快照使用 S000 的 `scripts/validate_delivery.py` 校验；S007 负责定义映射，当前执行者更新原系统后重新导出。小型单项正文计划人工核对同样关系，不将正文传入 JSON 校验器。工具验证显式映射，需求内容的完整性仍需 S006 审查。

## 任务与依赖

- 按连贯用户结果组织任务；共享模块和技术前置可以独立实施，但模块完成须覆盖完整业务流程。
- 为任务记录 `acceptance_ids`、`depends_on`、允许修改范围、风险、验证命令、阻塞条件和责任技能。
- 区分实现依赖、验证前置、外部联调和发布依赖；外部凭据或设备未提供时，项目内部可执行工作继续推进。
- 写出数据产出方、实际使用方、读取或触发时机、业务终态。配置能保存与配置会生效分别验收。
- 接口和 Schema 变更包含兼容、迁移与数据保护；高风险任务包含恢复方法。
- 并发任务检查共享文件、数据库、进程、端口和生成物的归属。没有隔离证据时顺序执行。
- 只纳入用户授权范围；不追加无关重构、框架升级或菜单。

## DoD

完成条件描述可观察业务结果及检查方法。例如配置修改后，业务操作读取指定生效版本，产生对应结果；导出文件可读取，内容对应批准的数据范围。只读功能验证查询结果、来源、权限和新鲜度，不强制添加写操作。

编译、路由、按钮存在、接口拒绝请求等各有检查价值，不能单独替代业务验收。原型、模拟、真实接入和未提供外部依赖分别登记。说明类修复只关闭说明类任务。

任务大小由职责、依赖和连贯验收决定，不限制固定文件数或步骤数。细分后的每项保留原始验收 ID，父任务仍负责组合结果。

## 委派与持续执行交接

只有授权允许委派时下发子任务，包含需求来源、验收动作、修改边界、依赖、禁止缩减项和证据要求。返回文件或 `OK` 只说明局部操作结果，父执行者读取产物并验证整合后的业务行为。

向 S008 交付完整 backlog、当前可执行项与已授权执行模式。用户要求全部完成时，单项结束后继续下一项，不把逐项授权作为默认流程。

## 输出与检查

输出完整需求覆盖表、任务 DAG、验收动作、执行顺序、阻塞项及授权边界。检查 ID 唯一、依赖存在且无循环、承诺有验收、验收有责任任务。计划任务使用 `TODO`，只有符合当前证据条件的实施任务才使用 `ACCEPTED`。不根据历史完成声明直接沿用当前通过状态。
