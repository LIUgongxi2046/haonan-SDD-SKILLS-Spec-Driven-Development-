# Haonan S012 技术文档交付

## 定位

把同一事实源翻译给不同读者。代码和可执行规范优先于旧设计文档；发现差异时报告漂移，不静默选择一边。

## 工作模式

- `PLAN`：定义受众、文档包、事实源和自动化路线。
- `GENERATE`：用户要求后创建/更新文档文件。
- `AUDIT`：检查准确性、完整性、链接、示例、版本和漂移。

## 事实优先级

按适用性：运行代码/配置/Schema > 生成并校验的 API 规范 > 当前测试与运行证据 > 已批准设计 > 旧文档 > 推导。

所有事实记录来源、版本/commit 和状态。缺少源码时可以生成设计态文档，但标题和页首必须标记 `DRAFT_FROM_DESIGN`，不得冒充已实现接口。

## 受众包

按需选择，不强制全部生成：

- 开发者：架构、环境、API、SDK、数据字典、扩展与贡献指南。
- 运维/SRE：部署、配置、秘密、迁移、监控、告警、备份、回滚与故障排查。
- 测试/安全：测试运行、数据集、门禁、威胁与残余风险。
- 产品/业务：功能、角色、流程、限制、管理员 SOP 和 FAQ。
- 外部用户：快速开始、认证、接口、错误、配额、示例和变更策略。

详细清单见 `references/document-bundle.md`。

## 生成步骤

1. 盘点代码、路由、Schema、OpenAPI、配置、命令、设计、报告和 Git 记录。
2. 建立文档—受众—事实源—生成方式—负责人索引。
3. 优先从代码/Schema 生成机器规范，再由同一规范派生人类文档。
4. 验证 API 示例、命令、链接、文件路径、版本和权限说明。
5. Release Notes 只基于实际 diff/commit/tag；指标改进必须有测量证据。
6. 建立 lint、链接检查、Schema 校验、示例测试和漂移检测。
7. 标记过期、未知、兼容/破坏性变化和迁移要求。

## 质量门禁

- OpenAPI/JSON/YAML 使用有效原始值，不把 URL 写成 Markdown 链接。
- 文档字段、状态和错误与代码/Schema 一致；差异有明确 issue。
- 示例可复制运行，秘密和真实个人数据已移除。
- 不虚构吞吐、准确率、成本下降、发布日期、版本特性或“零沟通成本”。
- 文档文件是 `CREATED`，实际 lint/link/schema/example 检查后才 `VERIFIED`。

## 输出

- 文档包索引、受众、路径、来源和状态。
- 已生成/更新文件与漂移问题。
- 验证命令和真实结果。
- 已知限制、未决问题和维护责任。

API 与发布文档需要代码缺失时，不拒绝所有工作：先输出缺口、可生成部分和补齐路径。默认不发布站点、不发送文档，也不修改外部系统。
