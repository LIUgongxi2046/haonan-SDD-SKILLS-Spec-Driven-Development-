# 长上下文与多任务实现检查

## 开始前

- 用一句话重述当前任务和 DoD。
- 列出必须遵守的接口、Schema、架构和用户约束。
- 标记用户现有改动、不可触碰区域和当前基线命令。
- 一次只执行一个明确任务；并行工作必须文件边界清晰。

## 上下文压缩

跨多轮时维护短交接摘要：

```text
goal:
completed:
changed_files:
verified:
failed_attempts:
constraints:
next_step:
open_risks:
```

摘要记录事实与状态，不记录模型内部思维过程。

## 防过度设计

- 新抽象是否由当前第二个真实用例驱动？
- 新依赖是否比现有能力显著降低风险或复杂度？
- 是否改变公共 API、数据模型或部署方式？若是，是否在任务范围内？
- 能否用更小、可回滚的改动满足 DoD？

## 跨层握手

- 前端类型与后端响应/错误实际一致。
- Agent 工具参数、权限、超时与后端契约一致。
- 数据字段、迁移、删除和缓存失效在各层一致。
- 测试验证契约和用户行为，不只验证内部实现。

## 模型或会话交接

不要按厂商名或主观印象固定分工。根据任务风险、工具能力、上下文长度、代码访问和验证能力选择执行者。交接必须包含上述事实摘要、diff、失败证据和下一验收点。
