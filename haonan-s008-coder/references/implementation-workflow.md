# 代码实施、验证与连续执行

根据用户实际授权选择。实施和验证在同一授权范围内持续进行；用户仅要求规划时不修改代码。外部发布与生产变更核对目标及已有授权，不从本地开发要求推导。

## 启动与续接

每项任务读取 [开发记录规则](../../haonan-s000-pmp/references/task-development-records.md) 与 [正文模板](development-record-template.md)。检索相关记录并核实当前代码；为当前任务创建或更新唯一 Markdown。本任务负责的全部必需验收通过后，仍需完成主记录、索引和关联文档核查，才能登记 `ACCEPTED`。技术交付任务、组合验收和独立测试分别对应计划中的检查，父功能完整业务验收要求继续保留。后续开发、测试及 Debug 均检索该记录。

读取当前文件、需求、DoD、接口规范、仓库规则和未提交改动，保护无关修改。读取 S007 工单中的用户结果、父功能与子任务、执行负责人、允许修改范围、共享资源负责人、前置产物及版本、环境和集成验收者，核实当前代码与输入版本，以及工作目录、数据库、服务、进程、端口和生成物的实际使用关系。存在责任或版本冲突时暂停对应动作，向协调负责人登记原因、影响和解除条件，继续本任务其他有依据的部分。跨会话读取 [续接要求](vibe-coding-issues.md) 和 [交付记录](../../haonan-s000-pmp/references/delivery-ledger.md)。

恢复全部未完成项、最新用户决定、当前修改、环境身份和证据。用户撤回或修改内容后重新读取文件，后续编辑基于当前保留内容。旧摘要、任务完成标签和子代理声明需要相应证据支持。

主 Agent 按 [S000 持续交付流程](../../haonan-s000-pmp/references/delivery-workflow.md) 核实当前开发目录与验证副本的用途，以及运行操作、资源责任和暂停决定；子 Agent 接收对应范围后核对当前文件。发现目录、任务记录与实际产物不一致时，定位相关差异并接续有效成果，不重新初始化项目或恢复用户已经撤回的内容。

从工单身份登记确认当前执行者是主 Agent 或哪个子 Agent，核实实际窗口名称、会话或 Agent ID、所属主 Agent 和任务接收状态。协调负责人即主 Agent，执行负责人即子 Agent；身份不明时暂停责任不明的写入并核实，不能自行宣告监督权限。

同时恢复阶段预期业务结果或必要前置产物、对应验收 ID、预计交付时间、检查间隔、带时区的下次检查时间、最近有效反馈及统计起点。S007 尚未提供这些安排时，由承担协调责任的主 Agent 根据当前工单补齐；已有用户规定直接继承。阶段安排服务于完整业务交付，不能替代父功能全部验收或改变授权范围。

获准执行协作时，主 Agent 核实实际 Agent ID 及状态查询、消息接收、继续任务、运行操作观察和会话续接方式，记录可用能力及实际检查依据。复用当前平台和既有任务来源，不为监督新增系统或执行者。会话续接同时核实运行中操作及已到期检查，不仅恢复任务文本；能力缺失时如实登记限制和责任，不承诺未具备的后台执行。

核对 S006 评审报告版本、范围、决议、关联 `issue_id` 及未解除条件，确认工单对应的设计依据和复核责任。修复结果连同产物与证据交给指定复核者，不能用编码完成代替问题关闭。设计依据需变化时由主 Agent 按 S004/S005 等所属责任安排修订与适用复核，S008 继续其他依据充分的工作。

检查本任务验收能否仅用自身输入和产物执行。若检查必须等待后续 UI 或集成，由主 Agent 在既有任务来源中明确组合验收责任及独立交付任务，保留原始验收 ID、证据和全部未完成项。当前共享校验器要求 `depends_on` 的前置任务达到 `ACCEPTED`；不可仅将整个前置任务改成通过，或移除真实依赖来开始后续工作。

## 实施循环

按 S007 分配的完整功能组织本轮实现与验证，核对菜单或页面入口、业务结果、适用技术步骤和开发集成负责人。同一功能内部可依照已满足的输入并行实施；功能所需产物就绪后及时完成接口消费、页面操作、结果读取及异常路径验证，不等待其他无依赖菜单或全项目前后端完成。开发期间的功能集成由 S008 执行，全部开发完成后启动 S009 的条件继续有效。

领取新功能前核查现有未集成功能集合及数量上限；默认每名功能负责人同时推进一个未通过开发集成验证的功能，总量遵守实际可用负责人数量及 S007 安排。优先处理已具备条件的集成、修复及必要依赖，子任务完成不自动成为启动更多功能的依据。达到上限时由主 Agent 处理阻塞或根据实际资源登记调整理由、接收能力及下次检查时间，执行者不自行扩大任务范围。受阻功能保留在集合中；已经通过开发集成、仅等待 S009 的功能单独登记并允许后续开发继续，最终业务完成仍等待全部必需验收。

1. 将对应验收动作转为可执行检查。缺陷从实际用户入口复现，记录请求、输入和失败结果；未验证的解释保持假设状态。
2. 根据风险选择单元、接口、集成、业务 E2E 或界面行为检查。只验证实现内部结构不足以完成业务验收；无需为无行为影响的小改动增加重复测试。新增或修改业务行为前，检查已有测试能否验证对应正常与异常行为。已有有效覆盖直接使用，缺少覆盖时补充；Red 必须来自业务行为缺失或错误，环境故障不能充当 Red。无行为影响的修改采用适用检查，不制造失败，不为形式另建测试文件。
3. 实施完整的授权功能，保留既有架构和命名。局部改动范围不能缩减已承诺结果。子 Agent 在分配范围内自主完成实现、验证、修复和记录；主 Agent 提供需求与设计指导并监督阶段结果。共享修改请求包含所需产物、业务依据、受影响使用方、负责人和接收条件。属于当前授权与写入责任时自行处理；属于其他负责人时交主 Agent 协调其交付，禁止同时接管。子 Agent 不自行改变其他执行者的责任、扩大范围或新增下级执行者。
4. 运行对应检查并检查服务端结果；涉及持久化时重新读取，涉及后续流程时验证实际使用方和业务终态。
5. 核对上下文、权限、Schema、数据版本、缓存和异步结果在各层一致。Agent 操作核对实际模型、工具、业务对象和结果采用。
6. 执行受影响的类型检查、测试和构建；共享组件修改根据实际使用处扩大回归。源码、生成物和运行进程须对应同一版本。修改期间执行直接相关的行为、类型和接口消费检查；交接时完成工单要求的全部必需检查，包括适用集成、业务 E2E 和工程检查。完整工程批次由指定负责人执行，其他执行者提供所需产物及针对性证据。所有验收仍覆盖完整承诺。联调采用 S007 指定的代码、协议、依赖、配置和数据版本及检查清单。必要输入变化时结束当前批次，登记新版本并复验受影响检查，不将不同版本结果合并为同一批次通过。
7. 检查 diff、生成文件、依赖、秘密和无关变动。相关代码、环境或数据前置改变后，将旧证据标记为待复验。复用通过证据前核验对应代码、接口、依赖、配置、环境、数据和使用关系仍然有效。影响证据的变化标记 `STALE` 并复验；同基线仅无关变化时可复用仍然适用的结果。基线改变时，当前共享校验器要求新基线的执行回执；保留原回执并按当前工具执行所需检查，不修改旧回执的基线、时间、输入摘要或执行结果。跨基线复用只能在配套工具实现与验证后按适用性复核规则进行，不能凭文档声明通过。影响不明时检查实际依赖，不能默认全部失效或默认全部有效。
8. 将实际结果登记到验收记录。未通过时定位、修复、重新运行；禁止降低断言、删除必需测试或隐藏错误取得通过。重复验证说明输入变化、失败或尚未解决的问题。环境故障与业务断言失败分别定位，修复后执行受影响检查。测试数量、重复次数和命令退出码均不能单独证明业务完成。
9. 当前任务的独立交付检查通过后继续已授权且依赖满足的下一任务，父功能按计划等待后续组合验收与独立测试；真实阻塞记录原因与解除条件，并推进其他可执行项。当前窗口按已分配责任连续推进，协调负责人维护完整 backlog，不重复领取其他执行者正在负责的任务；单执行者执行同等核查，可兼任全部责任。

证据的业务适用性与校验工具接受条件同时满足后才能登记当前通过。当前工具限制、拟增加的跨基线适用性复核及验证要求见 [S000 证据复用配套设计](../../haonan-s000-pmp/references/evidence-reuse-design.md)。这份设计不代表工具已经具备相应能力；工具不支持时记录实际限制及必要复验，不能以维护效率为由省略工具校验或业务断言。

每次变更按 `check_id` 核查需求与检查定义、源码和测试、直接及间接依赖、生成物、构建输入、配置、环境及数据身份，记录实际使用关系和影响依据。不能仅凭修改目录、文件后缀或新 commit 判定全部检查失效或全部可用。实际受影响证据标记 `STALE`；未受影响结果满足工具条件后继续引用。普通说明内容只有确认不参与构建、运行、测试及验收定义后，才能认定对对应检查无影响。当前工具要求的新基线重跑与业务变化导致的复验分别说明原因。

同一输入、环境、命令和检查定义下，能够覆盖共同要求且没有独立执行或隔离限制的检查由指定负责人运行一次，使用方引用原始证据并核实适用范围；功能专属断言继续执行。运行中检查可以等待并接收结果，不因窗口不同再启动相同检查；失败、输入变化或必要当前验证需要重新运行。优先使用现有差异、输入清单和依赖信息完成复核，未获得足够依据时执行覆盖不确定范围的检查，不循环生成相同分析。失败结果不能通过复核变为通过。

主 Agent 在任务接收、阶段产物、阻塞和交付时检查实际代码、记录和证据，执行中通过可用状态工具持续跟踪。发现问题时给出问题描述、依据、解决方案或定位步骤、处理者和完成条件；影响其他任务时同步对应子 Agent 并确认输入版本生效。子 Agent 回报指导执行结果，主 Agent 核验问题解除后继续安排。没有新增信息时不重复索取相同报告，复验继续遵守输入与证据有效性规则。

主 Agent 按登记的时间主动核查可用状态，缺少项目规定时执行期间默认每 15 分钟检查一次；阶段产物、失败或阻塞消息到达时及时处理。根据实际运行证据调整间隔时登记依据与下次检查时间，不能因没有结果持续延后。优先读取增量状态与已有产物，状态未变时不反复读取完整历史或索取长报告。子 Agent 运行长时间命令前提供命令或作业标识、可观察状态及预期产物；主 Agent 检查正常操作的运行状态，不为催报而终止操作。

到达检查时间没有反馈时，主 Agent 核查执行者状态、最近产物和运行中操作；执行者空闲且任务未完成时发送明确的继续任务或指导。写入状态无法确认时保留原写入责任，确认停止并完成交接后才能接管，禁止启动第二个执行者同时修改。运行环境不支持持续监督或恢复执行时，记录实际能力限制与未完成项，不声称后台监督已生效。上下文续接恢复检查安排，已过检查时间的任务及时核查；用户暂停期间仅完成状态与停止条件规定的必要处理，不继续日常监督或开发，恢复时根据当前授权更新安排。

每次实际检查引用状态或产物依据，登记时间、处理动作、负责人、预期证据及下次检查时间；已有工具结果可直接引用，不复制完整历史。消息事件及时处理，定时核查补充发现遗漏。指导已发送仅表示待处理动作，主 Agent 读取后续产物确认问题解除；执行者回报完成但缺少必要证据时继续核验。仍有可执行授权任务时，进度报告不结束监督，也不声称在会话停止后仍能持续检查。

跨任务指导进入原工单后，子 Agent 核实问题依据、动作、输入版本、写入责任、预期产物和接收条件；已有自主处理范围继续有效，不要求每项常规修改重新获准。执行结果提供对应产物、必要运行证据及剩余断言。共享能力交付后，由实际使用方完成接收检查；产出方的局部检查不能替代使用方消费。主 Agent 核验解除条件后维护原阻塞，问题仍存在时依据新增事实继续处理。

涉及验证程序、Schema 或协作工具的配套任务，检查实际项目调用入口、输入与输出、错误行为以及相关使用方。规则、配置或脚本文件存在不能证明调用已经生效；改动后验证使用方读取并执行当前版本。现有工具尚未支持的能力保留限制，不能修改旧回执、降低通过条件或将配套文档报告为工具完成。

## 业务完成自查

- 页面按钮是否执行承诺的操作，结果是否来自真实服务端或已明确授权的模拟能力？
- 配置记录是否被正确版本的运行逻辑读取，行为是否随配置变化？
- 状态更新是否对应实际业务结果，导出是否产生正确文件，审批之后是否到达承诺的后续步骤？
- 用户可以通过产品入口建立前置条件，还是只有预置记录能够运行？
- 异步返回、刷新、切换身份和跨页面跳转是否仍对应正确对象？
- 页面是否满足批准原型及项目规定的 1:1 还原条件，并且实际接口消费和全部适用业务操作已经通过？
- 子任务结果是否由指定使用方接收，父功能是否完成组合后的完整验收？

按实际功能选择检查，不给只读页面添加无关写操作。发现只有前端状态、通用记录或说明修改时，核对原始 DoD，继续保留未完成的业务承诺。变更产品范围需用户决定。

## 工程检查

- 从当前仓库确认语言、框架、包管理、格式化、类型检查、测试和构建命令，不预设技术选择。
- 依赖和 API 用法依据当前锁文件、本地源码及适用官方文档，未知内容明确记录。
- 源码、配置、静态资源或条件编译改变后，重新生成对应制品并核对实际加载位置；不复用不适用的旧包。
- 多平台交付分别构建和验证，维护修改文件、受影响页面或 API、回归用例的对应关系。
- UI 验证遵守视觉工具权限，使用确认的参考与视口；未执行视觉检查时不声明视觉一致。

前端开发读取批准页面映射、原型源码、CSS、Token、资源、全部控件与交互状态。按相同视口和状态核查结构、导航、栏目、尺寸、间距、字体、颜色、边框、圆角、阴影、图标、列表、表单、弹窗及抽屉；保留响应式、加载、空白、失败、等待、只读和权限状态。源码、DOM、计算样式检查和视觉比较分别记录实际证据，存在未解决的还原差异时页面保持未验收。

实施时复用批准原型的布局、CSS、Token 和资源，转换为工程组件时保留对应结构、尺寸及交互。公共布局与组件的唯一负责人在扩展使用前验证适用页面环境、视口和状态，提供原型与组件版本及有效证据；接收者核查当前页面是否属于已验证条件，新增条件执行相应检查。组件库默认外观不能替代批准高保真设计，不能为方便绑定数据而省略原型控件或改变布局。

每页结构与样式形成后立即核对原型并处理差异；业务接口绑定后检查实际内容、长文本、加载、空白、失败、权限及全部适用交互状态。主 Agent 或指定接收者在扩展复用与页面交付时核验这些证据。存在差异时在当前任务内修正，公共组件的已知差异未解决前暂停向更多页面扩展，同时继续其他不受影响的获准任务。交付时复用有效阶段结果并检查变化部分，不机械重复全部验证；原型还原工作不得集中推迟到全部开发完成后。

页面记录关联原型版本、组件版本、页面映射、检查时点、视口与状态、实际结果及差异处理证据。源码、DOM、计算样式和行为检查与视觉比较分别记录；视觉权限及未运行状态保持真实，不以增加开发检查为由调用未获准工具或要求用户逐页确认。共享组件修正后核查全部受影响页面的使用关系并完成适用回归。

比较条件包括浏览器、缩放、适用设备像素比、字体及资源加载版本、数据内容和交互状态，确保原型与实现处于可比较条件。已有项目级视觉授权在原范围内继承；未授权时记录 `VISUAL: NOT_RUN`。已授权比较覆盖完整页面和适用状态，识别环境渲染差异与产品差异，不能直接接受所有差异或擅自放宽阈值。动态区域处理保留业务内容与状态断言，图像差异指标仅辅助定位；页面最终验收仍满足原型、接口消费及全部业务要求。原型或共享资源变化时，按实际使用关系复验受影响页面。

## 状态与停止条件

任务使用 `TODO / IN_PROGRESS / IMPLEMENTED / ACCEPTED / BLOCKED`，证据使用独立状态。`IMPLEMENTED` 表示代码已具备待验收实现；`ACCEPTED` 需要所有关联的必需验收通过且证据适用于当前环境。

停止对应工作只限用户暂停、必要信息或资源缺失、授权不足、环境故障等真实条件。单个增量完成、上下文变长或已经输出报告都不构成放弃剩余授权任务的理由。上下文需要续接时保存完整当前状态。

暂停与取消按 [S000 状态与授权](../../haonan-s000-pmp/references/delivery-workflow.md) 执行。子 Agent 收到决定后停止新增实施和检查，处理当前命令并回报任务、作业或进程标识、最后有效产物、未完成项及实际停止状态。主 Agent 核验受影响执行者和资源，未确认停止的范围保持可见；仅完成必要结束处理、停止核验及状态保存，不以此继续业务开发。恢复后重新接收当前工单和写入责任，旧消息不得恢复已取消任务。

连续两个预定进展检查时点没有新增业务验收、经过验证的阶段业务结果、必要前置产物或阻塞解除时，主 Agent 检查失败原因、依赖、重复读取、重复验证和责任分配；新增代码、文档、测试文件及运行次数本身不能解除此检查条件。必要前置产物必须关联原始验收与实际使用方，并具有通过的检查。预计交付时间到达而产物缺失时立即检查，不能等待子 Agent 完成两轮回报。

主 Agent 登记已知原因或待验证假设、处理者、下一项定位或修复动作、预期证据及下次检查时间，并核验后续结果。正常长时间操作根据运行证据继续；需要调整方法、依赖顺序或责任时保留全部原始验收，责任转移遵守交接要求。单执行者承担相同检查责任。必要验证继续保留，不以重复次数判定失败；监督时间只触发检查，不自行增加费用或任务终止期限。

任务状态维护于项目唯一来源。子任务通过不能自动完成父功能；S009 启动条件沿用用户与项目决定，S008 自身的开发验证持续执行。

用户要求全部开发完成后启动 S009 时，主 Agent 按 S007 的明确任务清单核验整批 S008 实现、开发与集成检查、开发记录、适用评审条件及交接版本，确认对应写入结束后再启动。S009 自身的测试通过不进入其启动条件；属于本批开发交付的必需检查不能省略。原始业务验收中计划由 S009 执行的项目保持 `NOT_RUN`，父功能最终完成等待全部适用检查。任务计划中保留开发交付、独立测试与最终验收的对应关系，不能用阶段名称改变实际完成范围。

S009 接收后独立依据批准需求确定预期结果，读取开发证据并核查当前版本。测试失败由主 Agent 分配给 S008，附缺陷 ID、复现步骤、预期和实际结果、环境及版本；S008 修复并执行对应开发检查后报告修改范围与影响，S009 复验失败项及受影响流程，核验通过后关闭该缺陷。测试执行期间受影响批次暂停，版本改变后登记新批次；其他隔离且获准的检查可以继续。首次整批开发启动条件不要求每次缺陷修复都重新启动整套开发，但全部受影响验证仍须完成。必要的 S006 条件复核与交付审查按授权继续执行。

## 输出

报告实际行为变化、已验收范围、证据、失败或未运行项、剩余全部任务及阻塞原因。保持阶段进度可见，不让用户承担本应执行的验证。提交、推送、部署分别记录真实状态，继承已经明确的授权。

向 S009 交接完整需求和验收映射、开发任务与记录、代码及制品版本、实际环境和数据版本、模拟能力说明、启动及测试入口、开发检查证据、已知问题、未运行项和评审条件。接收者确认可读取并使用这些产物，主 Agent 记录交接时间和范围。报告明确区分开发交付通过、S009 独立测试通过和最终交付完成，未完成的后续阶段继续保留。

测试交接附检查影响范围、实际变更、原执行证据及适用性复核引用、未确定的依赖、必须由 S009 独立执行的检查和页面比较条件。S009 从批准需求独立判断预期与覆盖；共同检查复用不能免除其明确执行责任。报告分别统计本次实际执行、历史证据复用、需要复验和未运行内容，复核时间不能记成业务检查重新执行时间。

进度使用 S007 已登记的计算方法；缺少方法时，使用当前范围内全部必需验收通过的业务结果数量除以当前批准业务结果总数，注明统计时间、范围版本、环境、分子、分母和证据来源。分母按稳定业务结果 ID 计算，保留未开始、阻塞和待验收项；父子任务不重复计数，子任务增加或合并不改变分母。范围变化引用用户决定，证据失效的结果退出通过分子并列明待复验项。已实现待验收内容、阶段产物及技术任务状态单独报告，不能将验收数量比例解释为工作量或剩余工时比例；分母为零或范围未确定时不报告百分比。授权模拟环境的业务验收与生产接入分别统计，保持能力类型明确。

同一报告时段记录起止时间与经过时长，将新增业务结果、必要前置产物和阻塞处理对应到本期消耗。工具提供用量时登记主 Agent 与各子 Agent 的 Token 增量、来源、统计覆盖范围和可用分类；累计值使用本期起止差值，已经包含子 Agent 的汇总值不得重复相加。无法对应任务时保留会话或窗口统计范围；不可取得的用量明确记录，不能估算为精确值或填零。并行窗口时长不相加冒充项目经过时长，金额仅使用可靠费用来源。复用现有工具及记录，统计回到项目唯一来源，不建立另一套任务状态；费用和时间上限沿用用户规定。持续消耗但没有阶段结果时执行进展原因检查，不缩减设计、质量或验收。

多窗口交接由子 Agent 向主 Agent 及指定接收者提供当前产物、实现与文件范围、代码与环境版本、有效证据、全部未完成项、剩余断言及阻塞负责人。转移责任时，原执行者停止对应写入，接收者确认后更新责任并继续；主 Agent 接管同样遵守此条件。指定集成验收者读取产物并验证组合后的业务结果，主 Agent 核验接收并判断整体完成，不能仅采用子 Agent 的完成声明。主 Agent 向用户报告核验后的新增可操作功能、通过的验收、问题处理和后续安排，测试数量作为辅助。监督持续至全部获准任务完成或用户停止，确需用户决定的授权、范围和必要输入问题另行提交用户。
