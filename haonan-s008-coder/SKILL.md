# Haonan S008 代码实现

## 执行模式

- `SINGLE_TASK`：完成用户指定的独立任务及受影响验证。
- `AUTHORIZED_BACKLOG`：连续完成用户已授权的全部待办，单项验收后自动推进依赖满足的下一项。

根据用户实际授权选择。实施和验证在同一授权范围内持续进行；用户仅要求规划时不修改代码。外部发布与生产变更核对目标及已有授权，不从本地开发要求推导。

## 启动与续接

读取当前文件、需求、DoD、接口规范、仓库规则和未提交改动，保护无关修改。跨会话读取 [续接要求](references/vibe-coding-issues.md) 和 [交付记录](../haonan-s000-pmp/references/delivery-ledger.md)。

恢复全部未完成项、最新用户决定、当前修改、环境身份和证据。用户撤回或修改内容后重新读取文件，后续编辑基于当前保留内容。旧摘要、任务完成标签和子代理声明需要相应证据支持。

## 实施循环

1. 将对应验收动作转为可执行检查。缺陷从实际用户入口复现，记录请求、输入和失败结果；未验证的解释保持假设状态。
2. 根据风险选择单元、接口、集成、业务 E2E 或界面行为检查。只验证实现内部结构不足以完成业务验收；无需为无行为影响的小改动增加重复测试。
3. 实施完整的授权功能，保留既有架构和命名。局部改动范围不能缩减已承诺结果。
4. 运行对应检查并检查服务端结果；涉及持久化时重新读取，涉及后续流程时验证实际使用方和业务终态。
5. 核对上下文、权限、Schema、数据版本、缓存和异步结果在各层一致。Agent 操作核对实际模型、工具、业务对象和结果采用。
6. 执行受影响的类型检查、测试和构建；共享组件修改根据实际使用处扩大回归。源码、生成物和运行进程须对应同一版本。
7. 检查 diff、生成文件、依赖、秘密和无关变动。相关代码、环境或数据前置改变后，将旧证据标记为待复验。
8. 将实际结果登记到验收记录。未通过时定位、修复、重跑；禁止降低断言、删除必需测试或隐藏错误取得通过。
9. 当前任务验收后继续已授权下一任务；真实阻塞记录原因与解除条件，并推进其他可执行项。

## 业务完成自查

- 页面按钮是否执行承诺的操作，结果是否来自真实服务端或已明确授权的模拟能力？
- 配置记录是否被正确版本的运行逻辑读取，行为是否随配置变化？
- 状态更新是否对应实际业务结果，导出是否产生正确文件，审批之后是否到达承诺的后续步骤？
- 用户可以通过产品入口建立前置条件，还是只有预置记录能够运行？
- 异步返回、刷新、切换身份和跨页面跳转是否仍对应正确对象？

按实际功能选择检查，不给只读页面添加无关写操作。发现只有前端状态、通用记录或说明修改时，核对原始 DoD，继续保留未完成的业务承诺。变更产品范围需用户决定。

## 工程检查

- 从当前仓库确认语言、框架、包管理、格式化、类型检查、测试和构建命令，不预设技术选择。
- 依赖和 API 用法依据当前锁文件、本地源码及适用官方文档，未知内容明确记录。
- 源码、配置、静态资源或条件编译改变后，重新生成对应制品并核对实际加载位置；不复用不适用的旧包。
- 多平台交付分别构建和验证，维护修改文件、受影响页面或 API、回归用例的对应关系。
- UI 验证遵守视觉工具权限，使用确认的参考与视口；未执行视觉检查时不声明视觉一致。

## 状态与停止条件

任务使用 `TODO / IN_PROGRESS / IMPLEMENTED / ACCEPTED / BLOCKED`，证据使用独立状态。`IMPLEMENTED` 表示代码已具备待验收实现；`ACCEPTED` 需要所有关联的必需验收通过且证据适用于当前环境。

停止对应工作只限用户暂停、必要信息或资源缺失、授权不足、环境故障等真实条件。单个增量完成、上下文变长或已经输出报告都不构成放弃剩余授权任务的理由。上下文需要续接时保存完整当前状态。

## 输出

报告实际行为变化、已验收范围、证据、失败或未运行项、剩余全部任务及阻塞原因。保持阶段进度可见，不让用户承担本应执行的验证。提交、推送、部署分别记录真实状态，继承已经明确的授权。
