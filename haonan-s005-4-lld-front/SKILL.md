# Haonan S005-4 前端 LLD

## 定位

把体验与接口契约细化为当前代码库可实现的前端结构。先检测框架、路由、状态管理、样式和测试工具，避免强推固定技术栈。

## 工作模式

- `DESIGN`：创建前端 LLD。
- `AUDIT`：审查现有前端结构、状态、契约和体验风险。
- `MIGRATION`：规划框架、设计系统、路由或状态管理迁移。

## 输入处理

读取 PRD、原型/UI、HLD、后端/Agent 契约、现有代码和浏览器支持目标。缺少某项资产时可生成标记假设的草案；只有关键 API、路由或不可逆平台差异无法判断时才阻塞。

事实标记为 `EXPLICIT`、`INFERRED`、`UNKNOWN`。不从视觉稿推断计费、权限或数据规则。

## 设计步骤

1. 盘点当前框架、构建、路由、目录、状态、样式、组件和测试约定。
2. 建立路由/屏幕—FR/AC—API—状态追溯表。
3. 定义页面、布局、功能组件和共享组件边界及数据所有权。
4. 设计本地状态、服务端状态、URL 状态、表单状态和持久化边界。
5. 定义 API/事件适配、缓存、失效、重试、取消、乐观更新和并发冲突。
6. 覆盖加载、空、部分数据、错误、权限、离线、超时、重复提交、成功和恢复。
7. 如涉及流式 AI，定义事件类型、顺序、断线续传、取消、工具状态、引用和安全渲染。
8. 落实 Token、响应式、键盘、焦点、屏幕阅读器、减少动态和国际化。
9. 为 H5、小程序等目标端定义条件编译、原生导航/自定义导航、安全区、TabBar、网络域名和静态资源解析规则。
10. 区分源码与生成目录；构建物记录源 commit、目标端和生成时间，IDE/上传工具只能打开已验证的目标目录。
11. 设计单元、组件、契约、可访问性、视觉和 E2E 验收边界。

## 必须交付

- 路由与页面拓扑、组件职责和依赖方向。
- 前端状态模型和事件/副作用表。
- API/流式事件 TypeScript 或等价类型契约。
- 错误目录到 UI 恢复动作的映射。
- 表单、权限、缓存、离线和并发策略。
- 设计 Token、响应式、可访问性与 i18n 实施规则。
- 资源契约：本地/远程资源边界、包体预算、引用完整性、选中态资产、运行时下载失败和平台合法域名要求。
- 测试边界、性能预算和可观测性事件。

详细模板见 `references/frontend-contract.md`。

## 质量门禁

- 不渲染未清洗的模型/用户 HTML；XSS、URL、文件和 Markdown 边界明确。
- 不只设计 happy path；所有适用状态有可观察反馈和恢复动作。
- 类型、状态和错误名与后端/Agent 契约一致；差异进入 S006，不静默改名。
- 不输出或要求内部思维链；流式 UI 只展示产品允许的状态、证据和结果。
- `CREATED` 的类型示例不等于代码编译通过；实际 typecheck/test/build 后才 `VERIFIED`。
- H5 构建通过不能证明小程序可预览；每个目标端分别构建、检查产物和执行平台验证。
