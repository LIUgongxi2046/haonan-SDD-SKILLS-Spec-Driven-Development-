# Haonan S000 产品研发项目编排

## 定位

把用户目标映射为最短、可验证的研发路径。默认只做范围识别、阶段路由和交接设计；只有用户明确要求时才继续调用或执行下游技能。

## 工作模式

- `ROUTE`：判断当前阶段与下一技能，适合单一请求。
- `PLAN`：生成多阶段流水线、依赖 DAG、里程碑和门禁。
- `AUDIT`：检查现有研发资产的缺口、错序、重复与风险。

未指定时，根据请求选择最小模式，不把简单任务扩展为全流程项目。

## 事实与状态

所有关键输入标记为：

- `EXPLICIT`：用户或现有文件明确给出。
- `INFERRED`：根据证据推导，必须写明依据。
- `UNKNOWN`：缺失且会影响决策。

所有交付状态只使用：`PLANNED`、`CREATED`、`OBSERVED`、`VERIFIED`、`BLOCKED`。没有真实工具证据时不得写 `VERIFIED`。

跨环境任务同时维护独立发布状态。源码、Git、部署、数据库、客户端构建和外部审核互不等价；本机测试通过不代表生产已部署，Git 已推送不代表小程序已上传。涉及任一发布面时，读取 [references/release-state-contract.md](references/release-state-contract.md)。

## 推荐生命周期

```text
S000 -> [S001] -> S002 -> S003-1 -> [S003-2]
     -> S004 -> S005-1/2/3/4 -> S006(DESIGN_REVIEW)
     -> S007 -> S008 -> S009 + S010 -> S006(RELEASE_GATE)
     -> S011 -> S012
```

方括号表示条件阶段。S005 分支按契约依赖并行，不强制固定串行；S009 测试计划可从 S002 开始，S010 威胁模型可从 S004 开始。

发布阶段按组件分叉：服务端走 `RELEASE_GATE -> 生产备份/迁移/部署 -> 生产验证`，客户端走 `RELEASE_GATE -> 构建 -> 平台预览/真机验证 -> 上传/审核`。只有对应分支都达到约定状态，才能声明整版发布完成。

## 路由步骤

1. 读取用户给出的文件、仓库与已有产物；先利用现有上下文，不重复索要。
2. 识别目标是设计、评审、实施、验证、发布还是文档。
3. 选择能完成目标的最少 Skill 集合，列出每项输入、输出和依赖。
4. 对缺失输入决定：可逆假设继续、降级为草案，或因不可逆差异而 `BLOCKED`。
5. 明确并行分支、质量门禁、回滚点和需要用户授权的动作。
6. 跨环境任务建立发布账本，记录当前 commit、构建物、目标环境、数据变更和外部审核状态。
7. 给出下一条可直接执行的 `$skill-name` 调用建议。

## 授权边界

- 路由、读取、分析和计划默认可执行。
- 修改代码、创建产品资产、运行有副作用的安全测试、部署、发布或外部写入，必须有用户明确授权。
- 不因用户说“跑完整流程”而自动扩大到生产部署、外部消息或不可逆操作。
- `commit`、`push`、部署、数据库迁移、客户端上传和提交审核是独立授权动作；前一步授权不得自动推导后一步。

## 输出格式

按需输出：

1. 当前判断：目标、阶段、模式与事实来源。
2. 资产盘点：已有、缺失、冲突和假设。
3. 流水线表：顺序、并行、输入、输出、门禁、负责人 Skill。
4. 风险与授权：阻塞项、爆炸半径、回滚点。
5. 发布状态：源码、Git、各目标环境、数据和客户端审核的已验证状态。
6. 下一步：最小可执行调用与所需上下文。

需要完整契约或机器校验时，读取 `references/pipeline-contract.md`；修改本系列 Skill 后运行 `scripts/validate_pipeline.py`。
