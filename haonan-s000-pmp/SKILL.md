# Haonan S000 产品研发编排

## 模式与责任

- `ROUTE`：选择适用技能并说明输入和输出。
- `PLAN`：建立需求范围、依赖、任务与验收计划。
- `DELIVER`：持续推进用户已授权的全部工作，直到验收完成、用户暂停或必要条件阻塞。
- `AUDIT`：核对现有需求、实现、测试、环境和交付状态。

根据用户动作选择模式。明确要求完成开发与测试时使用 `DELIVER`，同一授权在各技能和后续会话中继承；只要求规划或回答问题时维持对应范围。简单任务可直接调用适用技能，完整业务设计和验收要求仍须保留。

## 范围依据

目标范围依次依据用户最新明确决定、批准需求、确认设计。运行代码说明当前实现；缺少实现的需求仍属于承诺范围。记录 `EXPLICIT`、`INFERRED`、`UNKNOWN`，推导不能静默改变承诺。

多任务、跨会话或涉及业务验收时读取 [交付记录](references/delivery-ledger.md)。存在既有任务系统时映射其字段，避免另建竞争事实源。单项明确修改可在当前任务记录同样的信息，无需强制完整流水线。

## 技能选择

| 技能 | 适用工作 |
|---|---|
| S001 | 产品目标、用户价值、战略与商业假设 |
| S002 | 需求、业务动作、规则和验收范围 |
| S003-1 / S003-2 | 信息架构与原型、视觉系统与界面审查 |
| S004 | 系统边界、组件职责和架构决策 |
| S005-1 / S005-2 | 数据生命周期、后端接口和业务状态 |
| S005-3 / S005-4 | Agent 执行与采用路径、前端上下文和交互状态 |
| S006 | 设计一致性、业务完整性和发布证据审查 |
| S007 | 完整任务覆盖、依赖与验收责任 |
| S008 | 单项实现或持续执行已授权待办 |
| S009 / S010 | 业务测试、AI Evals、适用安全验证 |
| S011 / S012 | 环境运行与发布、当前交付记录及文档 |

技能按依赖调用，允许设计、测试规划和安全分析同步推进。仅在授权允许委派时安排代理；主执行者保留整体验收责任。

S003-2 根据本次实际界面工作选择：新视觉方案或跨页面视觉系统使用设计模式；复用现有风格进行局部修复使用限定范围审查或实施模式。后端任务无需因为项目存在界面就增加视觉设计。图像生成和视觉工具遵守用户要求，不作为所有任务的默认前置。

## 持续交付循环

1. 读取全部尚未验收需求、最新用户约束、当前文件和环境身份，检查已有证据是否仍适用。
2. 由 S007 检查每项承诺都有任务及验收，选取依赖满足的任务交给 S008。
3. S008 实施并运行对应检查；S009 根据需求独立核对业务结果。测试问题进入同一任务记录。
4. 对真实阻塞记录原因、已检查内容和解除条件；继续其他可执行工作。外部依赖不足不自动阻塞项目内部工作。
5. 单项完成后自动推进下一项已授权任务；阶段进度用消息说明，不能依靠用户反复输入继续维持执行。
6. S006 检查范围完整性和证据适用性。只有全部当前承诺通过验收，才报告该范围完成。

用户改变范围时按当前决定更新记录，已撤销内容不恢复。会话压缩、工具切换和代理交接保留完整未完成集合、授权、修改范围和证据路径，详见 [流水线协作](references/pipeline-contract.md)。

## 状态与授权

执行状态、证据状态、能力类型分别记录。设计产物已创建不能推断产品已实现；局部检查通过不能推断业务已验收。完整交付声明使用交付记录检查结果及 S006 的语义审查。

正常实现、修复和对应验证继承用户已有授权。部署、外部消息、生产数据变更等核对具体目标和已有授权；确实缺少必要授权时只暂停受影响动作，不重复申请已明确授权的步骤。

涉及发布时读取 [发布状态](references/release-state-contract.md)，分别记录源码、Git、构建、运行环境、数据库、上传与审核结果。

## 输出

按任务需要提供当前范围、模式、任务状态、业务验收结果、阻塞项和实际证据。百分比附需求与验收分母；未完成范围明确列出。报告从唯一当前记录派生，不按文档数量或测试数量宣告完成。
