# Codex 执行规则

各技能的详细流程、字段、图表、示例和验收清单共同构成执行规范。`haoemr-experience.md` 补充业务完成、连续执行、证据和环境要求，不能代替正文的专业交付物。局部更新需要保留原有有效要求；不得通过概括模板缩减用户承诺。

## 阶段与授权

1. 完整读取当前技能正文及 `haoemr-experience.md`。根据实际任务读取其引用的详细参考。输出全部适用章节，每项不适用内容说明依据；不能因篇幅或上下文长度省略。
2. 文中的 Phase 表示工作依赖与质量检查。用户要求分阶段确认时等待确认；已有完整实施授权时连续执行，在阶段之间报告进度，不反复要求用户输入继续。只有影响必要决策的未知信息才暂停依赖该信息的工作。

阶段提示的执行条件统一为：`INTERACTIVE_REVIEW` 仅在用户明确要求逐阶段确认时使用；`CONTINUOUS_DELIVERY` 用于已有完整产出或实施授权。各正文和交互范例中的“询问”“暂停”“等待确认”均受此条件约束。连续执行模式下保留相同专业检查与交付内容，阶段结束后直接推进下一项；必要范围决定尚未明确时只等待对应决定。
3. `PLAN`、`AUDIT`、`REPORT` 保持各自范围；用户授权实施与测试时持续完成全部待办。技能中的设计模式不改变 Codex 的协作模式。
4. 读取已有 PRD、HLD、LLD、代码、测试和用户决定。缺少关键设计时补充设计任务并持续推进已授权部分；缺少文件名称不自动等于缺少必要信息。未知内容不能填写为已确认。
5. 前置依赖按数据、后端、Agent、前端、集成组织。记录已满足、待完成和不适用节点，保留真实依赖；独立任务可推进。不会因一个外部接口受阻而停止全部内部开发。
6. 文件、框架、数据库和阈值示例用于展示设计完整度。实际技术选择依据当前工程与批准设计；保留原模板要求的机制与验收，不能借适用性删除功能。变化中的 API、价格、法律和标准查证当前来源。

## Codex 能力与边界

- 使用当前可用的文件、命令、联网和提问工具。Cursor 的 `@文件` 表示需要实际读取的上下文路径；不要求用户切换 IDE。旧技能简称对应已安装的 `haonan-s...` 名称。
- `Hook`、Fork、MCP、模型缓存、隔离环境与子代理均需确认运行环境支持。架构设计必须写明实际承载位置和可验证行为。只有用户或适用规则授权委派时才执行委派，主执行者继续负责整体验收。
- 图像生成、截图及视觉比较遵守用户限制。未获准时继续文本规范、DOM 行为及其他适用检查，明确视觉部分未验证。已有风格及参考直接继承；仅在需要用户选择方向时提供完整可选方案。
- 设计依据输出为决策摘要、可检查的理由、证据和权衡，不生成或展示内部推理过程。
- 测试与实施使用获准的真实数据、真实服务和实际结果。用户禁止模拟时不创建模拟服务、合成样本或替代模型响应。模板数据只描述格式，不能登记为测试证据；真实样本缺失时保留具体阻塞。
- 错误在发生位置明确报告；不吞掉失败，不使用替代结果伪装成功。重试和人工处理必须有业务依据、预算与终止条件。保留已确认的操作授权，不引入无依据的发布审批。
- 安装、提交、推送和部署分别核对授权与目标。不得使用 Git 命令恢复用户代码；文件恢复按当前用户规则操作。文档中的服务恢复要求指适用的发布或数据恢复流程。

## 完成与证据

任务状态、验收状态和能力类型使用 [交付记录](delivery-ledger.md)，发布与环境状态使用 [发布状态](release-state-contract.md)。原模板中的勾选、`DONE`、`APPROVED` 和 `GO` 必须注明所评估范围；设计通过不能代表业务已经实现。

每个必需验收项记录入口、角色、输入、动作、预期结果、实际断言、运行命令、代码与数据版本、原始结果。合法成功路径和权限拒绝路径分别检查。配置必须验证读取与生效，Agent 必须验证实际调用与业务采用，持久化必须重新读取。

报告模板中的数字、时间和结论只能由实际运行结果填写；没有证据时使用 `NOT_RUN`、`BLOCKED` 或 `INSUFFICIENT_EVIDENCE`。类型检查、路由数量、按钮存在和命令退出码不能代替业务验收。长任务续接保留全部未完成项、当前授权、用户纠正、资源归属及有效证据。
