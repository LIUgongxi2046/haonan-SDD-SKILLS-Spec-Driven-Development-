# S000 证据复用配套设计

日期：2026-11-17。状态：配套设计，工具尚未实施；执行条件以实际工具能力及当前用户授权为准。

## 适用范围与当前执行条件

本设计服务于 S007 的验证安排、S008 的证据复用及 S009 的独立验收与回归。当前 `validate_delivery.py` 要求每份通过证据的 `baseline_id` 与交付记录中的当前基线一致，并核查执行回执、输入及产物摘要。当前可直接复用同基线且全部输入仍有效的证据。切换基线时，现有工具仍需新基线的执行回执；S007、S008、S009 必须按实际能力执行，不能声明跨基线复用已经生效。

基线必须如实描述代码与环境组合，不能为保留通过结果而继续沿用已失真的基线。原始执行回执不可修改；执行时间、命令、退出码、代码输入、数据与环境身份属于原执行事实。跨基线复用保留这些事实，并单独记录当前适用性复核。

## 共同产物与责任

S007 在工单中指定检查范围、所有影响结果的输入、环境与数据身份、使用方、证据负责人和需要重新运行的条件。S008 收集实际输入与变更依据，执行适用性复核及必要复验。主 Agent 检查引用完整性，S009 独立判断证据能否支持当前业务验收，S006 核查完成声明范围。

任务与验收状态继续维护于项目唯一来源。配套工具仅生成可验证证据及校验结果，不维护另一套任务状态，不改动用户的验收要求。

证据适用性以 `check_id` 及其实际输入、断言和环境为单位判断，保留完整项目基线用于追踪。项目版本变化只说明需要重新判断适用性，不能单凭版本 ID 推断所有检查的业务结果均失效。工具需要分别表达实际影响、适用性判断和当前工具接受结果；旧版本工具要求重新执行时保留真实限制，不能绕过校验。

共同检查由 S007 指定唯一执行者。输入、环境、命令、检查定义、隔离条件及责任要求一致，且能够覆盖所有接收方对应断言时，可以共享同一原执行证据；任务专属断言仍须执行。运行中检查先接收实际结果，不自动重复启动；失败、输入变化、用户要求当前执行或 S009 独立执行条件产生相应新检查。该安排使用现有计划和执行工具，不建设另一套调度系统。

## 拟增加的数据结构

共享 Schema 使用显式新版本，保留现有版本的原校验行为。新版本增加可选的适用性复核引用；没有引用时继续要求原执行基线与当前基线一致。

| 记录 | 必需内容 |
|---|---|
| 原执行证据 | 原 `evidence_id`、`check_id`、证据类型、原基线、原回执位置及摘要；原执行记录保持不变 |
| 当前基线 | 当前代码与制品身份、依赖和配置版本、环境与数据身份、模型及工具版本等适用信息 |
| 适用性复核引用 | `revalidation_ref`、复核记录摘要；引用实际工具生成的独立复核记录 |
| 适用性复核记录 | Schema 与工具版本、复核时间、原证据及回执摘要、目标基线 ID 与描述摘要、当前验收及检查定义摘要、输入清单与摘要、使用关系清单、变化项与影响依据、复核命令及结果 |
| 检查适用范围 | 稳定 `check_id`、全部关联验收 ID、断言和命令、直接及间接依赖、生成物及构建输入、环境与数据身份、使用方、独立执行要求及失效条件 |
| 本次处理与依据 | 实际执行、历史证据复用、需要复验或条件不足；对应实际变化、影响分析依据、未知范围及责任者；与原检查 PASS/FAIL 分别表达 |

目标基线描述必须包含实际文件、制品或可核查的环境身份，不能只有自行填写的名称。变更范围需要来自实际版本差异和依赖关系，输入清单必须覆盖共享代码、生成物、测试代码、配置及执行命令实际使用的资源。原证据的内容和身份不能因为被新基线引用而改变。

版本差异与文件摘要只提供部分依据，依赖关系应来自当前工程实际构建、导入、配置和运行使用信息，复用成熟工具已有能力。纯说明变更须确认不参与构建、运行、测试及验收定义；不能仅按目录或后缀分类。检查清单和使用关系不能仅由执行者自行声明为完整而免于核查。矩阵展示字段不直接写入旧 Schema，所有机器字段采用明确版本及验证规则。

## 复核执行与接受条件

1. 读取并校验原回执与全部原产物，确认原检查实际执行成功，执行期间输入未变化，原证据的检查 ID、类型、命令和验收范围均可追踪。
2. 读取当前验收定义、检查代码与命令、依赖和使用关系。验收定义、检查行为或必要输入变化时执行相应原检查，不能仅生成复核说明。
3. 对照原始输入清单和当前实际输入，验证内容、依赖解析及使用关系一致；新增的实际依赖也必须识别，不能只检查原列表中仍存在的文件。无法证明输入清单完整时执行原检查。
4. 确认环境和数据条件仍适用。可变数据库、身份权限、外部服务、模型服务或时间敏感结果不能仅凭配置文件未变化判定可复用。需要不可变快照、可核查版本或其他足以证明结果适用的实际依据；依据不足时重新执行相关检查。用户要求当前实时验证的检查必须重新运行。
5. 复核工具记录原回执摘要、当前输入、目标基线、验收与检查定义、实际核查结果，生成独立复核记录。复核只证明历史结果对当前范围的适用性，报告不得把复核时间写成原业务检查重新执行的时间。
6. 校验器读取原执行回执和当前复核记录，核验所有引用、摘要、目标基线、当前输入及适用条件。任一必要依据缺失、发生变化或复核失败时，拒绝复用并明确失败原因；需要重新执行的检查由责任执行者运行。

只接受直接引用原执行回执的复核记录，不允许以多次复核引用相互替代原始执行。每次校验继续检查当前输入，复核记录产生后发生的变化同样会使其失效。原回执与复核记录分别保存并展示，失败的业务执行不能通过适用性复核变为通过。

复核优先使用现有版本差异、输入清单和依赖信息，不能为复用持续重复读取同一材料。无法证明适用时明确指出不足依据与受影响或不确定的检查范围，由责任者实际运行相应检查；不把信息不足自动扩大为全部系统变化，也不默认未检查部分有效。必要范围确实覆盖全系统时保留完整验证要求。用户指定的当前执行和 S009 独立执行条件优先，工具接受历史证据不免除这些业务责任。

检查执行与适用性复核分别计数、计时。报告按稳定验收 ID 统计完整覆盖，按检查 ID 与运行次数统计本次实际执行，历史证据引用次数不增加本次执行数量。复核成本能够取得时单列来源和范围；无法取得时如实标识，不能为了节省统计工作制造数值。沿用已有记录和工具，避免新增重复状态来源。

## 共享工具的调整范围

- `delivery-ledger.schema.json`：增加显式版本及可选复核引用，保持原任务、验收、能力类型和状态含义。
- `validate_delivery.py`：保留原回执完整性与执行事实校验；具有有效复核引用时，增加目标基线适用性检查。不得仅删除原来的基线比较。
- 新增适用性复核工具及其记录 Schema：读取实际来源，运行核查并生成独立产物；无法证明适用时明确返回不通过，不生成替代成功结果。
- `delivery-ledger.md` 与证据说明：说明原执行、当前适用性复核、重新执行之间的关系，以及复核不能代替 S009 业务判断的边界。
- S007/S008/S009 调用方：使用相同的检查 ID、依赖及失效规则，识别当前工具版本，分别输出实际执行与复用事实；旧版本结构保持原校验行为，不自动接受新增字段。

当前配套设计不包含这些工具的已完成实现。正式采用跨基线复用之前，工具、Schema、文档与调用方需要作为同一项配套任务实施并通过验证；同基线复用继续使用现有工具能力。

## 工具实施的验收要求

使用获准项目中的实际检查产物验证以下行为，保存命令、输入、退出码和原始结果。本表定义验收要求，不代表已经执行。

| 条件 | 必须得到的结果 |
|---|---|
| 原版本记录、同基线且输入有效 | 保持现有接受行为 |
| 原版本记录跨基线且没有有效复核 | 明确拒绝 |
| 新版本记录跨基线，只有无关改动且全部适用性条件有依据 | 接受原执行证据与独立复核引用，保留两个时间与两种结果含义 |
| 必要源码、测试、接口、依赖、配置、数据或验收定义变化 | 拒绝直接复用，执行受影响检查 |
| 共享依赖新增、环境状态未知或动态服务结果没有当前依据 | 拒绝直接复用 |
| 原回执失败、回执或产物被修改、复核引用对象不符 | 明确拒绝 |
| 复核完成后输入再次变化 | 明确拒绝当前复用 |
| 仅某项检查受影响 | 保留其他符合条件的有效证据，不扩大为无依据的全部复验 |
| 任务或父功能仍有未通过的必需验收 | 继续保持未完成，复用不能改变需求覆盖判断 |
| 无关说明修改改变项目基线，检查输入及使用关系有完整未变化依据 | 新版本工具接受有效适用性复核，原执行时间保持不变；旧版本工具继续明确拒绝跨基线复用 |
| 文件位置未变化，但新增共享依赖或构建输入参与检查 | 识别依赖变化，拒绝直接复用受影响证据 |
| 多个任务使用同一共同检查，但仅部分断言已覆盖 | 仅接受已覆盖且条件满足的引用，其余专属断言继续执行 |
| S009 或用户明确要求当前独立执行 | 历史复用不能满足该执行要求，即使原证据完整仍保留待执行项 |
| 多项检查共享变化输入，另有检查无相关依赖 | 复验受影响检查，保留通过适用性复核的其他证据，不改变全部验收分母 |
| 复核信息不足或比较条件无法确认 | 给出具体不足依据，不生成成功复用结论，执行覆盖不确定范围的检查 |
| 同一历史证据被多个任务引用并完成当前复核 | 本次实际执行数不因此增加，覆盖按稳定验收 ID 去重，原执行与复核分别展示 |

实施后同时验证 S007 导出、S008 引用、S009 接收及 S006 完成审查能够读取这些记录。工具校验与业务语义审查分别通过后，才可以报告配套能力可用。
