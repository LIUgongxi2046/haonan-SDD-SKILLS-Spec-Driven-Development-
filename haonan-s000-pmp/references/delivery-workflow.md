# 产品研发持续交付流程

根据用户动作选择模式。明确要求完成开发与测试时使用 `DELIVER`，同一授权在各技能和后续会话中继承；只要求规划或回答问题时维持对应范围。简单任务可直接调用适用技能，完整业务设计和验收要求仍须保留。

## 范围依据

目标范围依次依据用户最新明确决定、批准需求、确认设计。运行代码说明当前实现；缺少实现的需求仍属于承诺范围。记录 `EXPLICIT`、`INFERRED`、`UNKNOWN`，推导不能静默改变承诺。

多任务、跨会话或涉及业务验收时读取 [交付记录](delivery-ledger.md)。存在既有任务系统时映射其字段，避免另建竞争事实源。单项明确修改可在当前任务记录同样的信息，无需强制完整流水线。

接续已有项目时，主 Agent 核验当前开发目录、代码及运行版本、用户暂停或恢复决定、实际执行者、共享资源归属、正在运行的操作、全部未完成任务和证据适用性。验证副本、历史副本及实际开发目录分别登记用途。检查范围由任务与实际差异决定，复用已核实且没有变化的上下文；不能每次接续都重新读取全部历史、重新初始化项目或覆盖现有成果。暂停期间保留当前状态，仅完成下文状态与授权规定的必要停止处理，不启动新的开发、验证或日常监督。

## 技能选择

| 技能 | 适用工作 |
|---|---|
| S001 | 产品目标、用户价值、战略与商业假设 |
| S002 | 需求、业务动作、规则和验收范围 |
| S003-1 / S003-2 | 信息架构与原型、视觉系统与界面审查 |
| S004 | 系统边界、组件职责和架构决策 |
| S005-1 / S005-2 | 数据生命周期、后端接口和业务状态 |
| S005-3 / S005-4 | Agent 执行与采用路径、前端上下文和交互状态 |
| S006 | 设计一致性、业务完整性和发布证据审查 |
| S007 | 完整任务覆盖、依赖与验收责任 |
| S008 | 单项实现或持续执行已授权待办 |
| S009 / S010 | 业务测试、AI Evals、适用安全验证 |
| S011 / S012 | 环境运行与发布、当前交付记录及文档 |

技能按依赖调用，允许设计、测试规划和安全分析同步推进。仅在授权允许委派时安排代理；主执行者保留整体验收责任。

主 Agent 沿用用户指定或已经生效的身份，按 S000 维护跨任务执行安排及整体接收，按 S007 维护计划，按 S008 指导开发、处理问题并接收开发产物；子 Agent 按任务负责完整业务结果或明确的前置能力。S009 独立判断测试预期与结果，主 Agent 负责调度与解除阻塞。角色可以在授权范围内兼任，Skill 切换不自动改变身份或写入责任，不因增加协调职责再创建一个主 Agent。运行中检查的频率、反馈入口和责任交接沿用 S007/S008 的同一安排。

仅在实际需要的范围内核查规则版本、项目采用位置、执行任务、工具支持与运行证据。现有项目使用自己的验证程序时，读取实际入口及其输入规则，不能从 S000 工具的能力推断项目工具已经具备相同能力。必要能力尚未支持时，安排有明确接收条件的配套任务；其他依据充分的工作继续。采用规则、修改工具和验证效果分别需要对应证据，不增加平行状态系统。

S003-2 根据本次实际界面工作选择：新视觉方案或跨页面视觉系统使用设计模式；复用现有风格进行局部修复使用限定范围审查或实施模式。后端任务无需因为项目存在界面就增加视觉设计。图像生成和视觉工具遵守用户要求，不作为所有任务的默认前置。

## 持续交付循环

1. 读取全部尚未验收需求、最新用户约束、当前文件和环境身份，检查已有证据是否仍适用。
2. 由 S007 检查每项承诺都有任务及验收，选取依赖满足的任务交给 S008。
3. S008 实施并运行开发与集成检查；S009 按用户和项目约定的启动条件独立核对业务结果。用户要求全部开发完成后测试时，由主 Agent 核验指定批次全部开发交付、开发集成检查及记录、待测试版本和对应写入结束后启动 S009；S009 自身的通过结果不作为启动前提。测试问题进入同一任务记录，返回 S008 修复后由 S009 复验失败项及受影响范围。
4. 对真实阻塞记录原因、已检查内容和解除条件；继续其他可执行工作。外部依赖不足不自动阻塞项目内部工作。
5. 单项完成后自动推进下一项已授权任务；阶段进度用消息说明，不能依靠用户反复输入继续维持执行。
6. S006 检查范围完整性和证据适用性。只有全部当前承诺通过验收，才报告该范围完成。

选择可执行任务前，同时检查实现依赖与验收执行依赖。前置能力的独立交付检查应当能够用已有输入及自身产物执行；需要后续页面或业务流程的检查安排到明确的组合验收任务，并关联原始验收 ID。父功能继续等待全部适用开发、集成及独立测试结果。发现相互等待时，由 S007 维护任务和验收归属，再确认执行者使用生效安排；不得通过直接标记整个前置任务完成、删除真实依赖或缩减断言解除等待。

主 Agent 根据实际检查结果处理下列条件，处理记录直接引用现有任务、工具结果和产物，不复制完整会话历史。

| 实际检查条件 | 主 Agent 的处理动作 | 接收依据 |
|---|---|---|
| 子 Agent 等待共享接口、文件或环境 | 核对必要性及当前负责人，明确需交付的产物、版本和使用方；只暂停依赖该输入的动作 | 负责人交付，使用方读取生效版本并通过对应检查 |
| 达到 S007/S008 的进展检查条件或预计交付时间已到 | 核查运行操作、当前实现、剩余断言及原因；形成有依据的定位或修复动作，必要时调整依赖顺序或交接责任 | 新增有效阶段结果、必要前置产物或阻塞解除证据；代码与消息数量不代替结果 |
| 产物已具备但尚未完成集成 | 核实集成输入和接收能力，优先安排当前功能的接口消费、页面操作及适用异常检查 | 指定接收者验证组合后的业务结果；未集成功能数量仍按现有计划控制 |
| 子 Agent 回报完成，必要证据不足 | 指定缺失检查及负责人，保持对应待验收事实 | 当前版本的完整必需证据，保留未执行的独立测试 |
| 长时间操作正常运行 | 使用作业标识及实际运行信息观察，保留资源负责人和下一检查时间 | 有效运行进展或终态结果，不为催报终止正常操作 |
| 执行者空闲且仍有可执行获准任务 | 核实任务接收、依赖、未集成功能数量和写入责任后，继续原任务或分配下一任务 | 实际接收及后续产物；写入状态未知时不得增加第二个写入者 |
| 验证反复因版本变化而无法接收 | 核查实际变化、检查输入和资源责任，安排受影响批次使用明确版本，隔离其他获准修改 | 当前有效批次及按影响确定的复验；不能修改旧回执或忽略工具校验 |

每次处理明确事实或待验证假设、动作、执行者、预期产物、接收条件和下一检查时间。指导已发送、执行者已接收、问题已解除分别依据实际结果判断。必要的信息和资源请求交给既有负责人；明确需要用户决定时只暂停对应动作。处理后核验结果，未解除时依据新增事实调整动作，不能重复发送相同催促代替定位。

前端按批准原型及 S007/S008 的开发中检查要求接收；公共组件扩展前、页面结构与样式形成后及业务绑定后检查适用条件，差异在当前任务内修正。沿用已有视觉授权，未执行部分保持 `NOT_RUN`。完整业务结果包含全部适用层次，局部代码或通用工程检查通过不能关闭页面与业务验收。

用户改变范围时按当前决定更新记录，已撤销内容不恢复。会话压缩、工具切换和代理交接保留完整未完成集合、授权、修改范围和证据路径，详见 [流水线协作](pipeline-contract.md)。

## 状态与授权

执行状态、证据状态、能力类型分别记录。设计产物已创建不能推断产品已实现；局部检查通过不能推断业务已验收。完整交付声明使用交付记录检查结果及 S006 的语义审查。

证据复用同时核验业务适用性与实际工具接受条件，原执行回执保持不变。同基线结果也需要当前输入、环境和使用关系支持；跨基线能力以已实施工具和验证结果为依据。配套要求见 [证据复用设计](evidence-reuse-design.md)。当前脚本保留现有实现，该设计中的跨基线能力尚未实施。必须当前执行及 S009 独立执行的检查继续保留，业务影响判断与工具要求分别说明。

正常实现、修复和对应验证继承用户已有授权。部署、外部消息、生产数据变更等核对具体目标和已有授权；确实缺少必要授权时只暂停受影响动作，不重复申请已明确授权的步骤。

用户暂停或取消时，主 Agent 根据原话明确作用范围，停止派发受影响工作，将决定传达到相关子 Agent，并核查实际执行状态、运行中命令和共享资源。停止某项任务、全部开发、测试与本地服务分别处理；仅暂停开发不自动终止用户仍需使用的服务，用户要求停止本地项目时核验对应服务和进程。停止决定不需要再次批准。

各执行者停止新增修改及检查，依据工具支持和操作性质取消运行中的工作，保存已有成果、未提交变更、原始结果及全部未完成项。涉及不能安全中断的事务或外部操作时，只进行必要的结束处理和状态查询，不启动下一项业务动作；记录实际状态及处理依据，不能将状态未知报告为已经停止。不得终止无关进程、删除工作成果或恢复用户已经撤回的内容。

暂停后的必要操作仅限传达决定、取消或结束当前操作、核实停止及保存状态。主 Agent 逐项登记已停止、仍在结束处理和无法确认的实际事实，收到回报后核验相应作业或进程；发送通知不等于全部停止。工具不可达时保留原资源责任、已尝试动作及未确认范围，不另派执行者同时写入，也不声称停止已经完成。停止核验结束后终止日常监督和自动续派，不以保存记录为由继续开发。

恢复需要当前有效授权。主 Agent 重新核对任务、执行者、写入责任、运行操作、版本及证据，接收者确认当前任务后继续；旧提醒、排队指令和迟到回报不得恢复已取消工作或覆盖当前决定。状态记录沿用项目唯一来源，本节事实描述不自动增加既有 JSON Schema 的状态值。

涉及发布时读取 [发布状态](release-state-contract.md)，分别记录源码、Git、构建、运行环境、数据库、上传与审核结果。

## 输出

按任务需要提供当前范围、模式、任务状态、业务验收结果、阻塞项和实际证据。百分比附需求与验收分母；未完成范围明确列出。报告从唯一当前记录派生，不按文档数量或测试数量宣告完成。

阶段报告引用 S007/S008 的统一统计范围，说明新增可操作功能、通过的验收、必要前置产物、阻塞处理结果、未完成责任与下一动作。消耗采用实际可取得的时间和 Token 来源，不重复累计主 Agent 已包含的子 Agent 用量。监督动作数量和 Skill 文本更新不计作产品完成；规则实际运行的效果按 [调度行为核查](orchestration-validation.md) 中适用证据说明，未验证的结论保持未验证。
