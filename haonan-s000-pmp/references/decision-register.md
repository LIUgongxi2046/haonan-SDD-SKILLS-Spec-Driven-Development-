# 决策记录与影响管理

S001/S002 定义目标或规则、S004/S005 确定设计、S007 安排依赖时使用。复用项目已有 ADR 或决策表；同一决定使用稳定 ID，各技能引用同一当前记录。

| 字段 | 要求 |
|---|---|
| `decision_id` | 稳定标识 |
| 事项与范围 | 需要确定的业务或设计问题、适用模块与环境 |
| 来源类型 | `EXPLICIT / INFERRED / UNKNOWN`，同时引用消息、批准资料或观察证据 |
| 当前建议与依据 | 说明可检查的理由、约束和影响；无需为固定数量编造候选 |
| 决策状态 | `PROPOSED / NEEDS_INPUT / CONFIRMED` |
| 决定与权限依据 | 谁作出当前决定、是否属于已有实施授权、决定来源 |
| 影响关系 | 需求、验收、任务、接口、文档及证据 ID |
| 重新评估条件 | 哪些需求、环境变化或新证据需要重新核查 |
| 验证与交接 | 验证假设的方法、通过依据、责任技能及接收任务；没有实测值时保留待验证 |

来源类型和决策状态分别记录。资料中明确出现某句话只能证明其来源；不能自动推导用户已经批准该设计。常规实施选择在已有授权内由执行者决定并记录依据，影响范围、业务规则或外部操作的新决定遵循当前授权。

S000/S007 只等待依赖必要未知决定的动作，其他依据充分的任务继续。已有决定直接引用，不重复询问。决定变化时更新当前有效结论及影响关系，相关证据标记待复验；同步批准需求、设计与开发记录，不能仅更新聊天说明。

S001 的目标、资源和商业假设交给 S002 时，分别标明批准目标与待验证假设；S002 将其映射到具体业务规则和验收。S004 的 ADR 引用相应 `decision_id`，S007 在工单中注明依赖的当前决定。决定已确认仅证明可以按该方向实施，效果是否成立继续依据实际验证。
