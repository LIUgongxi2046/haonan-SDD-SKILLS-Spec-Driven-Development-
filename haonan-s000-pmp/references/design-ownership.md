# 设计维护责任与依赖

各技能保留完整专业内容；同一字段、接口或状态规范明确唯一维护位置，其他文档引用其版本与位置。跨文档重复展示时注明来源，变更后核查引用方。

| 责任技能 | 维护内容 | 交接重点 |
|---|---|---|
| S002 | 业务目标、组织职责、规则与验收 | FR/BR/AC、权限及决策来源 |
| S003-1 / S003-2 | 交互流程、页面状态 / 视觉 Token 与资产 | 需求映射、动态状态及已确认方向 |
| S004 | 系统边界、组件归属、ADR 和 NFR | 技术选择、依赖、运行与信任边界 |
| S005-1 | 数据语义、实体、来源、生命周期与查询要求 | 字段、身份、事务和检索边界 |
| S005-2 | API、序列化、任务接口、持久化、授权、超时和通知 | 可调用能力、任务 ID、状态、错误和事件 |
| S005-3 | 模型调用、工具选择、节点流转、上下文及结果采用 | 引用后端能力，定义 Agent 内部执行 |
| S005-4 | 页面组件、状态、请求及结果呈现 | 引用数据与接口规范，明确前端转换和使用 |

后端管理 Agent 注册、版本和任务生命周期时，记录后端负责的管理与执行接口；Agent 内部节点和条件路由由 S005-3 维护。S005-2 可以引用编排图及输入输出，无需另建独立节点规范。前端 Token 引用 S003-2 当前规范，框架映射由 S005-4 维护。

执行顺序由实际依赖确定：数据、接口或状态尚未定义且会影响正确性时先完成对应设计；输入已经满足或不存在依赖时可推进独立工作。每个节点记录 `SATISFIED / PENDING / NOT_APPLICABLE` 及依据，`PENDING` 仅阻塞依赖它的动作。任务缺少某个命名文档时核实已有代码和批准规范能否提供必要信息。

并行执行仍遵守当前委派授权及共享资源归属。明确调用规范不能替代最终集成验收；各端完成后由 S009 验证完整业务结果，S006 检查共同规范及版本一致性。
