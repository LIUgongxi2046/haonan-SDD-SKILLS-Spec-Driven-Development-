# S 系列协作规则

## 阶段责任

S002 保留完整需求及动作，S007 保证任务覆盖，S008 实施，S009 验收，S006 核对业务完整性和证据。S000 负责持续推进已授权范围，S012 维护同一当前记录。

S000 的协调负责人沿用实际主 Agent；S007 提供完整范围、实现与验收依赖、执行责任、检查安排及接收条件；S008 接收当前任务并交付完整实现、开发集成证据和剩余断言；S009 按约定条件接收测试范围并独立判断。各 Skill 使用同一主 Agent 身份和项目任务来源。主 Agent 的跨任务处理遵循 [持续交付流程](delivery-workflow.md)，具体开发监督沿用 [S008 实施流程](../../haonan-s008-coder/references/implementation-workflow.md)，不重复建立调度记录或要求子 Agent 向多个协调者汇报。

每项 S008 任务同时交付一份项目内开发记录。S007 指定身份与路径，S008 编写并更新索引，S009 读取与核实，S006 检查记录完整性，S012 维护知识关联；具体要求见 [任务开发记录](task-development-records.md)。任务完成后无需等待最终项目交付才保存记录。

启动相关开发、测试、Debug、安全或部署诊断时检索记录，并读取当前代码及环境确认有效性。历史记录不能替代批准需求和当前执行证据。设计内容的唯一维护位置见 [设计责任](design-ownership.md)。

设计、实现、验证和发布分别记录。读取日志是观察，创建文件是产物生成，对应验收通过才可登记任务 `ACCEPTED`。状态和字段见 [交付记录](delivery-ledger.md)。

## 依赖与授权

- 必需依赖：缺少会影响正确性或安全的输入，仅阻塞相关任务。
- 条件依赖：只有对应平台、功能或发布范围存在时启用。
- 建议输入：有帮助但不必作为所有任务前置，假设需要标注。

用户授权完整开发与测试时跨技能继承，单项完成后继续。生产发布、外部消息和新增影响需要具体授权；已经明确的授权无需重复请求。委派只在允许时使用，主执行者保留最终责任。

用户要求全部开发完成后启动 S009 时，该阶段条件在 S000、S007、S008 和 S009 中保持一致。S008 持续执行开发检查及集成，全部约定开发交付满足后交给 S009；独立测试结果保持原始验收归属。进入 S009 后发现缺陷，由主 Agent 指定 S008 负责人修复，S009 接收修复版本并复验；发送修复指导或执行者声明完成不关闭缺陷。用户暂停优先于此前持续执行安排，恢复时重新核验当前事实，保留已满足且仍有效的条件。

## UI 与上下文

界面设计按本次改动选择新设计、限定审查或实施。保留已有风格与用户工具限制，不因项目有 UI 就强制生图。实际代码用于现状判断，用户决定与批准需求用于目标范围。

已有批准高保真原型且要求 1:1 还原时，S007 安排公共组件复用前、页面形成及业务绑定后的检查，S008 在开发过程中处理差异，主 Agent 根据适用证据接收；S009 独立检查完整范围。原型、接口消费和业务断言均属于对应页面完成条件，未执行视觉检查单独记录，不用结构或行为证据推断视觉通过。

## 交接字段

保留完整承诺和验收 ID、所有未完成任务、当前文件变动、实际环境、有效证据、用户约束及来源、授权、依赖阻塞和下一可执行项。只传一个下一步或成功任务列表不能完成长任务交接。

跨任务指导沿用任务 ID，保留问题证据、执行动作、责任者、必要输入及版本、允许修改范围、预期产物、接收者和检查时间。子 Agent 核实接收并回报实际产物、运行证据或阻塞；主 Agent 核验实际使用方接收后判断问题解除。责任转移保留原执行者停止写入与接收者确认的依据；写入状态未知时不增加第二个执行者。

交接同时说明当前项目实际使用的工具入口、规则采用位置、能力验证依据及必要配套任务。规则已描述、工具已支持和实际效果已验证分别以事实说明。S009 保留独立判断，S006 核验完整性；任何阶段都不能仅因文档存在推断机制已生效。

跨环境工作同时使用 [发布状态](release-state-contract.md)。各发布面独立记录版本、目标和结果。
