# S 系列协作规则

## 阶段责任

S002 保留完整需求及动作，S007 保证任务覆盖，S008 实施，S009 验收，S006 核对业务完整性和证据。S000 负责持续推进已授权范围，S012 维护同一当前记录。

设计、实现、验证和发布分别记录。读取日志是观察，创建文件是产物生成，对应验收通过才可登记任务 `ACCEPTED`。状态和字段见 [交付记录](delivery-ledger.md)。

## 依赖与授权

- 必需依赖：缺少会影响正确性或安全的输入，仅阻塞相关任务。
- 条件依赖：只有对应平台、功能或发布范围存在时启用。
- 建议输入：有帮助但不必作为所有任务前置，假设需要标注。

用户授权完整开发与测试时跨技能继承，单项完成后继续。生产发布、外部消息和新增影响需要具体授权；已经明确的授权无需重复请求。委派只在允许时使用，主执行者保留最终责任。

## UI 与上下文

界面设计按本次改动选择新设计、限定审查或实施。保留已有风格与用户工具限制，不因项目有 UI 就强制生图。实际代码用于现状判断，用户决定与批准需求用于目标范围。

## 交接字段

保留完整承诺和验收 ID、所有未完成任务、当前文件变动、实际环境、有效证据、用户约束及来源、授权、依赖阻塞和下一可执行项。只传一个下一步或成功任务列表不能完成长任务交接。

跨环境工作同时使用 [发布状态](release-state-contract.md)。各发布面独立记录版本、目标和结果。
