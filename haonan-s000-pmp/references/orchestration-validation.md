# 调度行为核查

本文件用于修改 S000 及跨技能调度规则后的质量核查。日常业务任务按自身验收执行，不要求每次交付都重复检查本表。核查使用当前任务来源与已有工具，保持用户授权、数据和资源边界。

## 核查方式与依据

格式、文档引用和内容保留检查验证文件完整性；根据输入情境检查规则及责任衔接属于文档情境推演；实际运行需要当前授权、工具调用、任务接收、产物和验证结果。三类结果分别记录。文档情境推演不使用伪造产品结果，不运行业务项目，不计作实际调度通过。独立执行者评估仅在当前委派已获准时使用，沿用指定模型和数量，不自动启动窗口。

每项核查保留情境 ID、输入材料及版本、适用规则、观察到的动作或文档依据、预期业务接收、实际结果及未验证部分。选择受本次修改影响的情境，必要新增条件加入既有清单；不以固定数量或得分替代判断。执行验证采用已有获准项目事实，缺少条件保留 `NOT_RUN`；不得为验证 Skill 擅自改变项目状态或恢复暂停任务。

## 调度情境与接收条件

| ID | 输入情境 | 应观察的处理与接收 | 必须保留的条件 |
|---|---|---|---|
| OR01 | 开发目录与验证副本并存，历史报告与当前任务状态不同 | 主 Agent 识别实际开发目录、当前代码与运行版本，读取相关产物和验收，接续全部未完成任务 | 保护已有成果；不能据旧副本覆盖开发目录或重新初始化项目 |
| OR02 | 前置模块的完成要求依赖后续页面，页面又等待整个前置模块完成 | S007 明确可独立交付的前置能力及检查，组合验收保留原始 ID；主 Agent 核验计划，执行者接收有效安排 | 不将完整前置模块直接标记通过，不删除真实依赖，父功能继续等待组合及独立测试 |
| OR03 | 子 Agent 在约定检查时点没有反馈 | 查询可用执行状态、最近产物及运行中操作；正常运行时保留观察，确认空闲且任务未完成时继续任务 | 写入状态未知时不增加第二个写入者，不因催报终止正常操作 |
| OR04 | 连续检查没有有效阶段结果，工具用量持续增加 | 主 Agent 核查原因与剩余断言，明确下一定位或修复动作、责任者、接收条件和检查时间，随后核验产物 | 消耗数据来自实际工具；不能仅改统计方式、增加窗口或降低验收 |
| OR05 | 多个功能实现已具备，等待开发集成，同时执行者请求开始新功能 | 核验现有集成输入、负责人及接收能力，按计划优先处理可执行集成，控制未集成功能数量 | 全部功能仍在分母中，受阻功能保留责任和后续动作 |
| OR06 | 子 Agent 报告完成，但缺少实际接口消费或结果重读证据 | 主 Agent 指定缺失检查与接收者，使用方验证当前产物，满足后维护对应状态 | 技术检查通过不代替业务验收；未运行项保持可见 |
| OR07 | 页面行为通过，但结构或样式与批准原型存在差异 | 按原型版本和适用状态核查，当前任务修正；共享组件已知差异影响其扩展使用 | 视觉授权按项目决定继承；未执行视觉比较不报告视觉通过 |
| OR08 | 文档修改改变整体版本，但具体业务输入未变；项目验证器只支持同基线 | 核查实际输入与使用关系，区分业务影响与工具要求；保留原回执，必要配套任务有实现与接收责任 | 配套设计不代表能力可用，不能改写旧回执或忽略校验；必要当前检查继续执行 |
| OR09 | 用户要求全部开发完成后启动 S009，目前部分功能已完成 | S008 继续开发检查和功能集成；主 Agent 核验全部约定开发交付后才启动 S009 | 首次启动不要求 S009 自身先通过，业务最终完成继续等待独立测试 |
| OR10 | S009 已启动，发现缺陷，S008 提交修复并声明完成 | 主 Agent 分配修复责任，S009 接收版本、复验失败项与受影响流程，依据结果关闭缺陷 | 不要求每项修复重新完成整批首次启动流程，不省略受影响验证 |
| OR11 | 用户暂停时仍有执行者或命令运行，之后收到阶段回报或发生上下文续接 | 主 Agent 按范围传达停止决定，核验执行者与相关作业，保存已有结果和完整未完成项；未确认状态保持可见，恢复获准后重新接收当前工单 | 仅完成必要停止处理，不继续开发或日常监督；不把通知发送当作全部停止，不因旧授权或迟到回报恢复已取消工作 |
| OR12 | 修改验证工具后文件存在、单项检查通过，但实际调用方仍使用旧版本 | S008 检查调用入口、运行输入及版本，使用方验证当前能力，S009 按适用范围独立接收 | 配置保存不代表读取生效，工具通过不代替业务断言，不能报告未具备能力 |

## 结果与修改范围

出现规则不明确或相互冲突时，在对应原章节修订，并核查相关调用方和交接要求。保留完整专业设计、示例和原始验收；不通过新增重复前言覆盖原正文。问题证据保留在独立核查记录中，Skill 正文维护当前有效要求。

报告分别说明格式及引用结果、文档情境推演结论、实际运行证据和未验证条件。规则指导了正确动作仍需核验实际产物、业务接收和进展；一次运行不能推断所有项目或全部场景的研发效率已经改善。
