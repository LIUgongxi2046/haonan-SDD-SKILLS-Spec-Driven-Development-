# 业务验收与测试矩阵

## 验收字段

| 字段 | 内容 |
|---|---|
| 来源 | 承诺 ID、批准需求、业务规则或真实缺陷 |
| 验收 ID | 稳定标识及负责任务 |
| 场景 | 角色、入口、环境、业务对象和前置 |
| 操作 | 实际输入和用户动作 |
| 预期 | 独立于实现的业务结果及来源 |
| 规则与未知条件 | 适用规则的来源和版本、字段范围及精度、状态与权限要求、适用非功能指标；必要未知及影响动作，历史参考不直接成为新规则 |
| 设计方法与覆盖对象 | 等价类、边界、决策表规则、状态转换、场景分支、错误推测或组合测试的选择依据，关联具体类别、条件或转换及其验收 ID |
| 优先级与执行方式 | 业务影响、实际使用频率、变更和历史问题依据，测试类型、自动化或可执行手工方式；优先级不取消必需验收 |
| 数据准备与目标分支 | 具体数据或受控引用、来源与许可、版本、合法或异常类别、刻意违反的规则、其余有效前置、关联记录、目标触发条件及实际校验结果 |
| 步骤与完成条件 | 操作、对象、数据引用、实际触发及观察方法、异步终态和时限；不依赖其他独立用例的偶然结果 |
| 准备与清理责任 | 可重复准备方法、共享环境唯一负责人、隔离及清理范围、输入变化对证据的影响 |
| 用例质量检查 | 覆盖完整性、预期准确性、触发有效性、可执行性、问题与处理证据；与产品执行结果分别登记 |
| 持久化 | 写入、重新读取和重复操作语义；只读注明不适用 |
| 后续使用 | 数据或配置使用方、生效版本、业务终态 |
| 检查 | `check_id`、证据类型、实际断言、命令、结果产物 |
| 检查输入与依赖 | 验收和检查定义、测试与业务源码、直接及间接依赖、生成物、构建输入、配置、环境和数据身份、实际使用关系及来源 |
| 失效条件与影响 | 当前实际变更、受影响使用方、需要复验的范围和理由；新增依赖与未知条件不能遗漏 |
| 证据与复核 | 原执行证据、原基线与时间、当前目标范围、复核依据及时间、工具能力和结果；原执行记录不变 |
| 执行责任 | 共同检查唯一执行者、使用方及任务专属断言；明确要求由 S009 独立执行或当前执行的检查 |
| 本次处理 | 实际执行、历史证据复用、待复验或未运行的动作及依据；与 PASS、FAIL 等结果状态分别记录 |
| 页面比较条件 | 原型和组件版本、页面映射、浏览器、视口、缩放、适用设备像素比、字体资源、数据及交互状态、授权范围和未解决差异 |
| 状态 | 未运行、通过、失败、过期、受阻及原因 |

缺少实现的承诺保留在矩阵。拒绝路径与合法成功路径分别记录。页面、按钮或接口数量不能替代业务动作覆盖。

详细用例保留现有 ID，与汇总矩阵引用同一测试资产。每条用例围绕一个连贯业务目的填写以下信息；只读、无 Body 或无持久化动作按实际情况说明，不为补齐模板添加无关行为。

| 内容 | 填写要求 |
|---|---|
| 身份与目标 | 用例 ID、原验收 ID、任务及模块、用户角色、业务对象、具体目标和批准依据 |
| 前置条件 | 当前环境、服务与配置、账号权限、可重复准备的实体和状态；秘密值使用受控引用 |
| 数据与设计依据 | 具体值或可读取的数据文件、类别及边界单位、规则或转换编号、目标分支、数据校验结果 |
| 操作步骤 | 每步写明操作、对象及数据引用；流程包含多个步骤时保留顺序及必要状态 |
| 预期断言 | 逐项列明适用 UI、接口、持久化、缓存、后续使用及必要日志结果，关联断言位置或实际观察方法 |
| 接口信息 | 方法、路径、必要 Header 名称、参数、Body 或受控引用、HTTP 与业务状态及响应结构；不适用项说明事实 |
| 异步与清理 | 可观察完成条件、时限、失败证据、准备和清理责任及范围 |
| 当前结果 | 检查 ID、输入版本、执行或复用依据、实际结果、缺陷及未完成项；设计文本不能填写成已执行 |

字段可以引用已有规范、数据和证据，避免复制相同正文。组合覆盖与数据参数化使用成熟工具，输出关联回原验收和检查 ID。用例质量检查可以记录问题条目，无须为每条用例新建独立报告。

## AI Evals

记录能力、风险、实际模型和 Prompt/工具/知识版本、样本来源与许可、分层、指标、阈值依据、重复次数、方差、人工复核和失败样本。功能运行、结果采用和效果评分分开报告。

## 执行记录

测试与 Debug 开始时检索 [开发记录](../../haonan-s000-pmp/references/task-development-records.md)，核实当前实现和环境；用例期望独立来自批准需求。浏览器检查按 [E2E 规范](browser-e2e.md) 记录真实控件、请求身份、业务终态和回归范围。执行后将证据关联回任务来源与对应开发记录。

使用 [交付记录](../../haonan-s000-pmp/references/delivery-ledger.md) 中的检查收据，或映射已有可信运行系统的同等字段。记录实际命令、环境、代码与数据版本、时间、退出码、断言结果和原始产物。

检查收据证明命令运行事实，仍需核对断言是否覆盖预期。测试脚本、业务代码和需求同时变化时检查预期依据，不能围绕当前输出修改通过标准。

同一原执行可以支持多个已覆盖的验收 ID，必须保持对应断言和范围可追踪；验收分母按原 ID 保留，运行次数与证据引用次数不增加业务完成数量。按 [业务验收与证据审查](acceptance-workflow.md) 判断复验和复用，原执行失败、条件失效或独立执行要求未满足时继续保持相应未通过状态。当前工具不支持的跨基线复用不得写成已接受。

这些字段用于既有矩阵和记录引用，不直接向严格 JSON Schema 写入未定义属性。复核工具与记录 Schema 完成实施之前，保留原工具支持的记录格式及实际执行条件；后续采用版本化配套结构时同时校验调用方。任务状态继续引用项目唯一来源。

统计分别记录需求设计覆盖、实际执行和当前有效通过，均注明对应范围、分母与证据。新增用例或多个数据参数不增加原始需求分母；历史比较使用可比较的规则、环境和版本范围。适用用例存在缺少预期、数据不可用或目标分支未触发等问题时，登记受影响范围和处理责任，不能因质量总分较高给出整体通过。

## 按需导出与字段映射

使用用户指定格式，未指定时沿用现有 Markdown 或项目测试资产格式，不同时生成全部格式。导出引用现有用例、验收和检查 ID，不重新编号替换原标识，不建立另一份独立完成状态。字段按目标工具实际要求映射，使用成熟 JSON、CSV 或 Excel 工具写入并重新读取核查；目标工具接口与导入要求需要使用时依据当前官方资料验证。

| 原测试资产 | 导出保留内容 |
|---|---|
| 用例及关联 ID | 原用例 ID、需求和验收 ID、检查 ID、模块及版本，保留相互映射 |
| 目标与方法 | 用例标题、业务目的、优先级及依据、设计方法、覆盖对象 |
| 前置与数据 | 可重复前置、角色、环境、具体数据或受控引用、合法或异常类别 |
| 操作与断言 | 有序步骤、操作对象、输入、逐步或最终预期、异步完成条件及适用层次 |
| 证据与结果 | 原始证据引用、当前结果、实际执行与历史复用区别、未运行项及问题 |

目标格式无法容纳全部内容时，将完整详细内容保存在同版本的关联正文或附件并保留可访问引用，明确导出范围，不默默省略必需字段。核查 ID 唯一性、用例数量、字段类型、中文及换行、多步操作、数据引用与预期映射；已授权的实际导入还要核验接收结果。仅完成文件生成时只报告文件验证结果，不能声明目标系统已导入。

导出注明源版本、时间及环境范围。普通说明和排版变化依据实际影响判断，预期、数据、步骤或前置变化须重新核查语义及受影响证据；版本记录使用既有来源，普通正文保留当前有效内容。格式输出不改变 S009 启动条件、独立测试责任或已有证据复用规则。
