# 业务验收与测试矩阵

## 验收字段

| 字段 | 内容 |
|---|---|
| 来源 | 承诺 ID、批准需求、业务规则或真实缺陷 |
| 验收 ID | 稳定标识及负责任务 |
| 场景 | 角色、入口、环境、业务对象和前置 |
| 操作 | 实际输入和用户动作 |
| 预期 | 独立于实现的业务结果及来源 |
| 持久化 | 写入、重新读取和重复操作语义；只读注明不适用 |
| 后续使用 | 数据或配置使用方、生效版本、业务终态 |
| 检查 | `check_id`、证据类型、实际断言、命令、结果产物 |
| 状态 | 未运行、通过、失败、过期、受阻及原因 |

缺少实现的承诺保留在矩阵。拒绝路径与合法成功路径分别记录。页面、按钮或接口数量不能替代业务动作覆盖。

## AI Evals

记录能力、风险、实际模型和 Prompt/工具/知识版本、样本来源与许可、分层、指标、阈值依据、重复次数、方差、人工复核和失败样本。功能运行、结果采用和效果评分分开报告。

## 执行记录

使用 [交付记录](../../haonan-s000-pmp/references/delivery-ledger.md) 中的检查收据，或映射已有可信运行系统的同等字段。记录实际命令、环境、代码与数据版本、时间、退出码、断言结果和原始产物。

检查收据证明命令运行事实，仍需核对断言是否覆盖预期。测试脚本、业务代码和需求同时变化时检查预期依据，不能围绕当前输出修改通过标准。
