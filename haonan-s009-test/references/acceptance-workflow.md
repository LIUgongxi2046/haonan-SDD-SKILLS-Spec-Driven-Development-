# 业务验收与证据审查流程

按请求组合模式，继承用户已有开发和验证授权。只读测试评估保持只读；已授权修复工作中的失败返回 S008 并持续复验。

## 独立验收范围

从最新用户决定、批准 PRD/AC、确认设计和缺陷复现建立分母。现有 routes、API、组件和测试辅助定位实现，缺少实现的需求仍保留为未验收。预期结果引用业务依据，不能从实现当前返回值直接生成。

读取 [测试矩阵](test-matrix.md) 和跨会话使用的 [交付记录](../../haonan-s000-pmp/references/delivery-ledger.md)。平台、角色、允许的模拟范围及视觉工具权限继承用户要求；条件专项见 [平台回归](project-specific-regression.md)。

接收 S007/S008 的完整需求映射、开发记录、适用 S006 条件、代码与制品、运行环境与数据版本、测试入口、实际负责人、已知问题和未运行项。用户要求全部开发完成后启动 S009 时，主 Agent 核验明确批次内全部开发交付和开发集成检查完成、对应写入结束后交接；S009 自身的通过结果不作为启动前提。接收历史证据不免除独立确定预期和核查完整范围的责任。

涉及主 Agent 指导后的修复或配套能力时，核对原任务和验收 ID、触发问题、当前产物、实际调用入口、使用方接收及剩余断言。现有规则已经描述、项目已经采用、工具已经支持和效果已经验证分别读取实际依据；仅有计划或设计时保留相应未运行事实。采用项目自己的验证程序时核查该程序的实际输入与结果，不直接套用其他校验器的能力结论。

对每项已批准功能提取输入输出、业务规则、状态变化、角色权限、跨模块交互、异常及适用非功能测试点，直接扩充既有矩阵。核实字段范围、精度、时间语义、允许与禁止动作、目标浏览器和设备、性能指标、可靠性及可访问性等适用依据。没有量化指标时可记录获准的实际测量，但不能自行设定验收阈值并报告通过；必要未知交给已有责任者处理，只阻塞依赖该条件的结论与动作。

已有开发记录、历史用例、缺陷及检索结果用于定位风险和覆盖遗漏，引用实际来源及版本。当前批准需求决定预期，历史资料不自动成为当前规则；隐含规则与新需求保持待确认，不擅自扩大产品范围。使用已有检索能力，不将特定外部检索 Skill 设为前置条件。安全、性能、兼容性等测试范围遵守用户授权与适用设计，不能因业务类别自动引入未经确认的行业要求或环境操作。

## 证据类型

分别报告 `STRUCTURE`、`STATIC`、`UNIT`、`API`、`SECURITY`、`BUSINESS`、`INTEGRATION`、`EXTERNAL`、`EVAL`、`VISUAL`。明确每种检查实际断言了什么：

- 页面标题、路由和启用按钮属于结构证据。
- 未认证请求被拒绝属于安全拒绝证据。
- 合法角色操作、服务端结果、刷新读取和后续使用构成相应业务证据。
- 模拟能力只证明授权的模拟范围，真实外部联调另行记录。
- 模型连接、Agent 运行、业务采用和 AI 效果指标分别验收。

测试总数和通过率只用于其对应分母，不能跨类型推导完成。

## 用例设计

1. 每项承诺关联稳定验收 ID、角色、入口、前置、操作和预期业务结果。
2. 写操作按适用性检查服务端持久化、刷新读取、幂等、并发、撤销或恢复；配置验证运行时生效，导出检查文件与来源。
3. 只读功能检查范围、来源、正确性、权限和新鲜度；不强制加入无关 CRUD。
4. 合法成功路径与权限拒绝分别测试，确认用户能够通过界面建立必要前置。
5. 检查加载、空、错误、部分数据、超时、重试、长内容和关键业务状态。共享组件覆盖全部实际受影响页面族。
6. Agent 检查操作者、角色、患者或其他业务对象、请求和结果来源；覆盖切换、延迟返回、跳转与采用。
7. AI Evals 记录样本来源、模型/Prompt/工具/知识版本、指标、阈值依据、重复与人工复核。能力实现未完成时保留该状态，评测分数不能替代功能交付。

根据业务影响、实际使用频率、变更范围、历史问题和质量要求确定优先级与测试类型，记录来源及选择理由。优先执行可发现关键业务失败的检查，同时保留所有必需验收及未运行状态；期限不能成为降低通过条件或删除场景的依据。测试类型不适用时说明事实依据，不能以低优先级解释需求已经满足。自动化依据行为可观察性、重复执行价值及维护成本选择，沿用既有框架和资产。

每项测试点按实际特征选择以下方法，并把覆盖对象映射到稳定用例及验收 ID。同一功能可以组合多种方法，不要求对每个功能机械使用全部方法。

| 方法 | 设计动作 | 覆盖依据 |
|---|---|---|
| 等价类划分 | 根据批准规则划分有效和无效输入类别，选取能代表对应处理逻辑的值；缺失、null、空字符串、空白、零值按实际语义分别处理 | 类别、规则来源、代表值及对应分支；不能仅凭表面格式相似判定行为相同 |
| 边界值分析 | 确定区间是否包含端点、单位与精度，再选择端点内外相邻可表示值及必要特殊值 | 长度计量方式、金额精度、时间单位与时区、分页及文件大小约束；相邻值不能一律使用加减整数一 |
| 决策表 | 列出条件、有效组合和动作，给每条规则指定预期；不可达组合给出约束依据 | 全部适用规则映射；合并规则前证明结果及相关副作用一致，不丢失条件覆盖 |
| 状态转换 | 列出当前状态、事件、前置条件、目标状态及副作用，检查允许与禁止转换 | 适用转换、事件顺序、重复与迟到事件、取消、恢复及终态规则；存在循环时按批准路径和风险确定覆盖，不能宣称穷尽无限路径 |
| 场景法 | 从用户入口建立前置，贯穿操作、接口、持久化、刷新及后续使用，分别设计主流程和适用异常分支 | 完整用户结果、分支触发点、恢复条件和业务终态；流程内相关断言保留 |
| 错误推测 | 根据历史缺陷和实际实现风险提出可复现条件，预期独立依据需求确定 | 历史来源或假设、触发条件、目标断言和实际结果；推测不直接作为缺陷事实 |
| 组合测试与 Pairwise | 列出参数、取值及约束，使用成熟工具生成并核查所需组合，记录覆盖强度与未覆盖范围 | 两两覆盖核查、约束一致性、必要高阶组合及已知风险组合；不能用组合数量代替覆盖证明 |

Pairwise 用于适合两两交互覆盖的范围。权限、金额、审批等关键业务按已批准规则保留必要组合和高阶交互检查，不能仅凭两两覆盖宣布完整验收，也不因某类功能名称自动要求无边界的全部组合。原要求明确全组合时完整保留；实际不可达组合以有效约束说明。原型、平台和设备组合沿用批准支持范围，不能从示例浏览器版本推导产品支持承诺。

用例以一个连贯业务目的组织，允许 UI、接口、数据库、缓存和日志中适用的多个断言共同验证该目的；无关目的分别安排。步骤提供明确操作、对象、输入及可观察完成条件，日志断言仅覆盖已有业务要求且不包含敏感正文。异步操作遵守实际终态、自动等待和时限规则。共享准备设施可以复用，但独立用例不依赖其他用例的偶然结果，清理只作用于本次获准范围。

重复用例按业务目的、规则、输入类别、状态、角色与断言比较；数据值不同可能代表不同边界或类别，不能直接合并。确认等效后可以复用或参数化，保留所有原验收映射与独立结果。同一功能修改只重新检查受影响设计及相邻依赖，避免每批用例重新分析全部需求。

每批用例形成后按完整性、预期准确性、触发有效性和可执行性自检，记录具体问题、影响用例、负责人及处理结果。质量检查依据事实，不采用固定用例数量、步骤数量、总分或修复轮次作为替代条件。设计检查通过仅证明测试资产满足对应设计条件，产品通过仍须实际执行及当前有效证据。

不伪造产品响应或测试数据。数据来源、处理许可和当前用户约束明确；缺少合法前置条件时记录阻塞。

数据集区分合法数据与刻意违反规则的异常输入。合法数据核验格式、边界、唯一性、计算、关联范围、状态及时间顺序；异常输入注明目标规则、预期拒绝和必须保持有效的其他前置，确认实际能够到达目标校验。多个无效字段组合需要独立覆盖依据，前置拒绝不能替代后续分支验证。数据版本、来源、具体值或受控引用及校验结果关联用例，输入本身的缺陷与产品缺陷分别归因。

准备数据时实际验证长度单位、数值精度、日期合法性、文件内容和大小，不采信未经核实的样例说明。关联数据按依赖准备，跨组织、权限、时间和业务状态约束分别检查；用户要求通过正式业务入口准备的条件继续保留。采用获准模拟数据时标明能力类型和环境，真实接入仍按真实数据及服务要求独立验收。数据生成、导入和清理遵守实际授权，不能自动导出生产数据或扩大外部操作范围。

共享环境重置前核实数据负责人、其他执行者、正在运行的检查及证据影响；具备隔离条件时只处理当前检查所需的数据。批次输入变化后按实际影响登记新版本及待复验项，不以每轮回归自动重置全部数据。准备与清理操作保留实际结果，不能依靠统一测试前缀证明环境隔离或外部发送安全。

## 执行与复验

读取当前代码、测试、环境和历史日志；确认源码、构建、运行进程、数据库、配置及账号身份。启动健康、登录和会话续期失败时处理测试前置，不能继续累积无效业务通过数。

执行前针对当前批次核查以下条件，已有仍有效的准备证据可以引用。发现问题修正对应测试资产或前置，不修改业务预期适应错误准备；只暂停依赖该条件的检查，其他获准且可执行的检查继续。

| 检查内容 | 执行前需要的依据 |
|---|---|
| 范围与预期 | 用例关联批准规则和原验收 ID，全部适用正常与异常要求均有覆盖或明确未运行项 |
| 具体操作 | 入口、对象、步骤、请求参数及数据引用可执行；共享前置可重复准备 |
| 数据有效性 | 合法数据满足必要约束，异常数据准确触发目标条件，受控文件和关联记录可用 |
| 权限与环境 | 账号角色、组织与对象范围、代码及服务版本符合当前检查条件，环境责任明确 |
| 结果判定 | 页面、接口、持久化及后续使用等适用断言可观察，异步终态和时限明确 |
| 隔离与清理 | 并发检查互不污染，准备和清理范围有授权，失败后仍可核实实际状态 |

用例准备问题和产品缺陷分别登记，缺少预期依据不能判定产品通过或失败。不能仅因文字中出现“成功”或“等待”就机械判定用例无效，应核查其是否同时具有具体状态、可观察结果及明确等待条件。

从相关检查开始，按影响扩大；记录命令、退出码、时间、输入版本、实际断言和原始产物。结果可通过 S000 的 `scripts/capture_check.py` 保存。该工具记录执行事实，S009 仍需审查检查是否覆盖预期结果。

执行前按稳定 `check_id` 核对批准验收与检查定义、命令和测试代码、业务源码、直接及间接依赖、生成物与构建输入、配置、环境、数据身份及实际使用关系。依据实际版本差异和依赖判断每项检查的受影响范围；不能仅凭目录、文件后缀、新 commit 或进入测试阶段判定所有历史结果失效或有效。变更说明由 S008 提供，S009 核查其完整性，尤其是共享输入和新增依赖。

| 当前条件 | 执行动作及证据处理 |
|---|---|
| 普通说明内容变化，确认不参与构建、运行、测试或验收定义 | 核实实际影响及工具条件后引用有效证据，不增加无依据的业务重跑 |
| 单个业务功能、失败项或相应检查发生变化 | 执行修改部分、失败用例及受影响的上下游流程，相关证据标记 `STALE` |
| 共享组件、接口、权限、Schema、依赖或配置变化 | 按直接和间接使用关系扩大回归，覆盖受影响页面、角色及业务状态 |
| 需求、预期或测试代码变化 | 审查变化依据和检查语义，重新执行受影响检查，不能围绕现有实现调整通过标准 |
| 数据、身份权限、外部服务、模型或时间条件变化 | 核查当前实际条件，依据不足时执行对应检查；配置文件相同不能证明动态状态相同 |
| 影响范围无法确认 | 检查实际依赖与运行输入，仍无法确认时执行覆盖该不确定范围的检查；范围涉及全部系统时执行对应完整检查 |
| 用户或项目要求当前完整验收，或明确由 S009 独立执行 | 按要求实际运行，不以历史结果或开发通过声明免除 |
| 本次无相关变化且存在有效历史执行 | 核查业务覆盖、输入和工具条件，满足全部要求后复用原证据 |

同基线复用仍需核验当前输入及环境有效。当前 S000 校验器要求证据 `baseline_id` 与当前基线一致，跨基线配套能力尚未实施；新基线按当前工具要求取得执行回执，不能改写旧回执的基线、时间、摘要或结果，也不能保持失真的基线名称。配套设计见 [S000 证据复用配套设计](../../haonan-s000-pmp/references/evidence-reuse-design.md)。工具完成实施并验证后，跨基线复用须同时提交不可变原执行证据和目标基线适用性复核，通过工具校验及 S009 语义审查。业务影响结论与工具要求的新执行分别说明，工具限制不表述为全部业务逻辑已经失效。

只复用成功且完整的原证据，逐项确认其断言覆盖当前批准预期。原证据没有覆盖的场景、未执行的分支、失败检查、失效输入及必须当前执行的检查继续运行；不能以抽查代替原有完整验收。共同检查仅在输入、环境、检查定义、隔离条件及责任要求一致时由唯一执行者运行，使用方引用证据并保留专属断言。不同执行责任或环境的检查不合并，S009 明确的独立执行不由 S008 证据替代。

复核优先使用已有差异、输入清单和依赖信息。无法证明适用时执行覆盖不确定范围的检查，不循环读取相同历史或反复生成没有新增依据的分析。检查失败后定位原因；重复执行必须对应修复、变化、当前验证要求或仍待确认的问题，不能不断重跑直到出现一次通过并隐藏其他结果。有效复核只证明历史成功对当前范围的适用性，不改变原检查的执行时间与执行者。

区分 `NOT_RUN / PASS / FAIL / STALE / BLOCKED`。脚本故障、配置错误、缺少数据、环境变化和产品缺陷分别归因；未知原因保留未知。修改测试期望需需求变更或测试错误证据，不能围绕实现缩减验收。

用户暂停或取消测试时按 [S000 状态与授权](../../haonan-s000-pmp/references/delivery-workflow.md) 传达并核验停止。保留已完成检查的原始结果，中断或未执行的检查不得计为通过；记录实际运行状态及停止原因。恢复时接收当前版本，按影响复验，保留全部原始验收和缺陷责任，不因收到旧回报自动恢复已取消批次。

测试期间固定当前批次输入，受影响输入变化时结束对应批次，登记新版本并复验必要检查；其他隔离且授权的检查继续。缺陷交给主 Agent 指定的 S008 负责人，包含缺陷 ID、原验收 ID、复现入口、输入、版本、预期、实际与证据。S008 修复并提供影响范围及开发检查后，S009 复验失败项和受影响流程，核查通过后关闭缺陷。发送修复请求、提交代码或修改状态均不能代替复验。

跨任务问题由主 Agent 按 [持续交付流程](../../haonan-s000-pmp/references/delivery-workflow.md) 指定处理者及接收条件。S009 明确所需输入与受影响检查，具备隔离和授权的其他检查继续；处理结果回到原任务与缺陷记录。环境问题解除后需要执行原业务检查，工具校验通过后仍需核实业务断言；协调处理完成不能直接改变独立测试结论。

## 完成与报告

业务验收列出承诺总数、已执行、通过、失败、未执行、受阻及证据过期数量。每个结论限定范围和版本。S000 的 `validate_delivery.py --require-complete` 检查完成记录的映射和执行证据；S006 复核语义完整性。

设计覆盖、执行覆盖和当前有效通过覆盖分别统计。设计覆盖分子是具有对应有效设计的稳定验收 ID，执行覆盖关联实际执行，当前通过覆盖按全部必需断言及证据适用性判断；用例数量和质量评分均不能替代这些分母。报告列出设计或数据准备问题、受影响用例和解除依据，不能把用例审阅通过、数据校验通过与产品通过合并。

报告分别列出本次实际执行、历史证据复用、需要复验及未运行项目。验收覆盖按稳定验收 ID 去重，实际运行次数单列；复用不计入本次执行数量，复核时间不替换原执行时间。复用条目记录原证据、目标范围、适用依据及工具结果，需要复验条目记录变化或不足依据、负责人及处理条件。检查选择、保留证据的依据和未确定范围可追踪，不另建一套任务完成状态。

前端接收原型版本、页面映射、开发中核对、未解决差异及当前浏览器和页面状态。S009 独立核验适用状态及原型还原要求，依照 [浏览器业务测试](browser-e2e.md) 使用已授权比较方法。结构、行为和视觉分别给出结论，视觉未运行继续保持 `NOT_RUN`；必要视觉验收缺少证据时不能宣告完整页面验收通过。

核心业务缺失时给出对应 `NO_GO`；证据不足使用 `INSUFFICIENT_EVIDENCE`。发布结论分别覆盖所需环境和外部依赖。局部测试通过保留其有效结论，不能扩大为全产品完成。
