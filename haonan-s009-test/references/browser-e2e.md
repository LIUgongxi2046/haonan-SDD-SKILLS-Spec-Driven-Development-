# 浏览器业务测试与开发记录

在生成、修改或运行浏览器 E2E 时读取。使用当前环境允许的浏览器能力和项目测试框架；不假定某个插件、登录脚本或特定 UI 库已经存在。视觉工具遵守用户限制，DOM 与行为检查和视觉验收分别记录。

## 入口与前置

1. 从批准 AC 和真实缺陷确定预期结果，检索相关 [开发记录](../../haonan-s000-pmp/references/task-development-records.md) 获取实现位置与验证入口。
2. 核实实际 URL、代码/构建版本、API 环境、账号角色及数据来源。需要登录时验证当前身份与会话有效性；登录失败不能登记业务检查通过。
3. 登录资料按环境和角色隔离，保存位置遵守项目秘密管理规则，日志与开发记录不包含 token。已有授权直接继承，缺少必要账号或数据时只阻塞相关用例。
4. 核查当前页面 DOM、语义控件、容器范围、弹窗、Tab、抽屉和条件状态。真实交互需要在获准范围进行，不能为探查控件自动提交或删除业务数据。
5. 接收批准原型与页面映射、CSS、Token、字体和资源、组件版本、开发中检查及未解决差异。登记浏览器版本、视口、缩放、适用设备像素比、数据与交互状态，确认原型和实现具备相同的比较条件。项目级视觉授权按原范围继承，不增加逐页用户确认；未授权时保持 `VISUAL: NOT_RUN`。
6. 核查用例准备是否可重复：前置实体、角色和数据引用可用，输入能够触发目标状态，预期可观察；同一业务目的的 UI、接口、持久化及刷新断言共同保留。异常输入说明刻意违反的规则及其他有效前置，不能用提前被拒绝的请求证明后续目标分支已经测试。
7. 共用账号、数据及环境时明确隔离和准备、清理责任，避免多个检查修改同一对象导致相互影响。数据重置按实际使用关系登记受影响证据，不因进入下一轮回归自动重置全部数据或重跑全部页面。

## 控件与 PageObject

记录页面、角色、环境、版本、控件类型、业务名称及定位依据。沿用现有 PageObject；定位器依据实际语义或项目稳定 test ID，并限定所属容器和可见状态。不得猜测控件类型，不通过选择首个匹配或强制点击掩盖定位歧义。

定位失败时保留错误并重新检查当前 DOM、身份、加载条件和页面版本。经证据确认页面变化后修改 PageObject，再执行对应测试；不自动轮换模糊定位器取得通过。

DOM/ARIA 结构摘要或 hash 只辅助判断定位资料是否可复用。角色、环境、业务状态和版本共同影响适用性；结构未变化不能证明业务行为未变化，不能替代回归。

高保真页面逐项核查布局、尺寸、间距、字体、颜色、图标、按钮、表单、弹窗及抽屉，并覆盖加载、空白、错误、权限、长内容和响应式等适用状态。获准图像比较应覆盖完整页面与这些状态，记录比较条件、差异及处理证据；差异数值只能辅助判断，动态内容处理不得隐藏必要业务区域或断言。不能自动更新参考图接受当前实现，参考变化须有批准原型依据。源码、DOM、计算样式与视觉比较分别记录，不跨类型推导通过。

## 异步动作断言表

| AC / 操作 | 触发条件 | 请求或事件身份 | 完成条件 | 页面结果 | 持久化/后续使用 | 时限与失败证据 |
|---|---|---|---|---|---|---|

根据动作选择实际完成条件：保存需要目标记录更新与重读；后台任务需要到达对应业务终态；导出需要文件生成和内容核查；搜索需要请求条件与结果内容一致。HTTP 成功、列表行数或 Toast 单独通过不能证明完整结果。

使用框架支持的自动等待、重试断言或有明确截止时间的状态轮询。必要的响应或下载监听在触发动作之前建立，并绑定请求对象、方法与业务 ID；禁止用固定等待时长代替完成判断。轮询到达时限时报告实际状态，不修改期望值取得通过。

## 执行、复验与记录

测试使用获准真实数据和服务。由 AC 建立正常、错误、权限和边界覆盖；未触发的分支保留未验证。记录初始失败与每次真实复验结果，不能合并成未经解释的通过。

修复后执行失败用例及改动影响的其他流程。共享组件、登录逻辑、接口或数据模型变化时重新确定回归范围；只重跑失败列表不能独立证明未运行范围仍然有效。

根据页面实际使用关系追踪共享 CSS、Token、字体、资源、组件、接口及状态来源的变化，选择受影响页面和适用状态。单页修改未影响其他输入时，对其他页面按证据规则核查适用性；不得仅因新 commit 或测试阶段变化要求全部页面重新执行。影响无法确认时执行覆盖不确定范围的检查，不以文件位置推断无关。当前基线限制与跨基线配套条件遵守 [证据审查](acceptance-workflow.md)，缺少工具能力不能声明复用已经通过。

页面原型还原在 S008 开发过程中完成，S009 接收并独立验证必要范围。发现未解决差异时交给主 Agent 指定责任者处理，关联原页面、原型、版本、状态及差异证据，修复后复验受影响部分。有效历史证据保留原执行时间和比较条件，当前复核与重新执行分别报告；用户规定的当前视觉验收和独立检查仍须执行。

执行证据关联 `check_id`、代码与环境、实际断言和报告。可用且获准时保存 trace；截图和视频仅在用户允许时启用。将证据引用更新到任务来源与开发记录，报告明确通过、失败、未运行和受阻的验收范围。
